# 동적 배열

고정 크기 배열은 처음 확보한 공간을 넘어서 원소를 넣을 수 없다. 동적 배열은 공간이 부족해지면 더 큰 배열을 만들고 기존 원소를 옮겨 이 제약을 해결한다. Java의 ArrayList, Python의 list, C++의 std::vector가 대표적인 예다. 끝에 원소를 추가할 때 가끔 복사 비용이 발생하지만, 여러 삽입에 나누어 계산한 비용은 amortized O(1)이다.

## 동적 배열의 구조

```java
public class DynamicArray<T> {
    private Object[] array;   // 내부 고정 배열
    private int size;         // 실제 원소 개수
    private int capacity;     // 배열의 용량

    public DynamicArray() {
        capacity = 10;  // 초기 용량
        array = new Object[capacity];
        size = 0;
    }

    // size: 실제 저장된 원소 수
    // capacity: 할당된 공간 크기
    // capacity >= size 항상 성립
}
```

`size`는 실제 원소 수, `capacity`는 확보한 공간의 크기다. 예를 들어 size가 5이고 capacity가 8이면 인덱스 0~4는 사용 중이고 5~7은 다음 삽입을 위한 여유 공간으로 남는다.

## Growth Factor (성장 계수)

배열이 가득 찼을 때 얼마나 크게 늘릴지는 성장 계수로 정한다. 크게 늘리면 다음 복사까지 더 많은 원소를 넣을 수 있지만, 당장 사용하지 않는 공간도 많아진다.

```java
// Growth Factor = 2 (Java ArrayList, C++ vector)
void grow() {
    int newCapacity = capacity * 2;
    Object[] newArray = new Object[newCapacity];
    System.arraycopy(array, 0, newArray, 0, size);
    array = newArray;
    capacity = newCapacity;
}

// Growth Factor = 1.5 (일부 구현)
void grow() {
    int newCapacity = capacity + capacity / 2;  // 1.5배
    // ...
}
```

- Growth Factor 선택의 trade-off:

- Factor: 2배:
  - 장점: 복사 빈도 낮음, 상환 비용 낮음
  - 단점: 최대 50% 메모리 낭비
- Factor: 1.5배:
  - 장점: 메모리 효율적 (최대 33% 낭비)
  - 단점: 복사 더 자주 발생
- Factor: 골든 비율 (φ≈1.618):
  - 장점: 이론적 최적, 메모리 재사용 가능
  - 단점: 실제 효과 미미

## Amortized O(1) 삽입 증명

한 번의 확장에는 O(n)이 들 수 있다. 그러나 끝에 삽입하는 n번의 연산에서 총비용이 O(n)임을 보이면, 한 번당 분할 상환 비용은 O(1)이 된다. 아래에서는 용량을 두 배씩 늘리는 경우를 총합 분석과 회계 분석으로 살펴본다.

- 증명 (Aggregate Method):
- n번 삽입 시 확장이 발생하는 시점: 1, 2, 4, 8, 16, ..., 2^k (where 2^k ≤ n)
- 총 복사 비용:
- = 1 + 2 + 4 + 8 + ... + 2^k
- = 2^(k+1) - 1
- < 2n, (since 2^k ≤ n < 2^(k+1))
- 일반 삽입 비용 = n
- 총 비용 T(n) < 2n + n = 3n
- 상환 비용 = T(n)/n < 3 = O(1)

- 증명 (Accounting Method):
- 각 삽입에 3 단위의 비용을 할당:
- 1 단위: 실제 삽입
- 1 단위: 나중에 자신이 복사될 때를 위해 저축
- 1 단위: 이전에 복사된 원소의 복사 비용 보조
- 확장 시점:
- n/2개의 새 원소가 각각 2단위 저축 = n 단위
- 복사해야 할 원소 = n개
- 저축된 n 단위로 복사 비용 충당 가능
- 따라서 모든 삽입의 상환 비용 = 3 = O(1)

## 삽입 연산 구현

끝에 넣는 `add(element)`와 중간에 넣는 `add(index, element)`를 비교해 보자. 둘 다 확장이 필요할 수 있지만, 중간 삽입은 공간이 충분해도 뒤쪽 원소를 이동해야 한다.

```java
public void add(T element) {
    // 용량 확인 및 확장
    if (size == capacity) {
        grow();  // O(n) 비용, 하지만 드물게 발생
    }
    array[size++] = element;  // O(1) 비용
}

public void add(int index, T element) {
    if (index < 0 || index > size) {
        throw new IndexOutOfBoundsException();
    }

    if (size == capacity) {
        grow();
    }

    // index 이후 원소들을 한 칸씩 뒤로 이동 - O(n)
    for (int i = size; i > index; i--) {
        array[i] = array[i - 1];
    }
    array[index] = element;
    size++;
}
```

## Shrinking Policy (축소 정책)

삭제한 뒤 여유 공간이 많아지면 작은 배열로 옮겨 메모리를 줄일 수 있다. 아래 구현은 원소가 남아 있고 사용량이 용량의 1/4 이하일 때 용량을 절반으로 줄인다.

```java
public T remove(int index) {
    T element = (T) array[index];

    // 원소 이동
    for (int i = index; i < size - 1; i++) {
        array[i] = array[i + 1];
    }
    array[--size] = null;  // 메모리 누수 방지

    // 축소 조건: size가 capacity의 1/4 이하일 때 절반으로 축소
    if (size > 0 && size <= capacity / 4) {
        shrink();
    }

    return element;
}

private void shrink() {
    int newCapacity = capacity / 2;
    Object[] newArray = new Object[newCapacity];
    System.arraycopy(array, 0, newArray, 0, size);
    array = newArray;
    capacity = newCapacity;
}
```

- 왜 1/4에서 축소하는가?
- 1/2에서 축소하면 문제 발생:
- capacity = 8, size = 4 상태에서:
- add → 확장 → capacity = 16
- remove → 축소 → capacity = 8
- add → 확장 → capacity = 16
- → thrashing 발생! 매 연산이 O(n)
- 1/4에서 축소하면:
- 확장 후 size = capacity/2
- size가 capacity/4가 되려면 capacity/4번 삭제 필요
- 그동안 O(1) 삭제가 보장됨
- → amortized O(1) 유지

## std::vector / ArrayList 구현 분석

### Java ArrayList

```java
// Java ArrayList의 핵심 구현 (OpenJDK 기준)
public class ArrayList<E> {
    private static final int DEFAULT_CAPACITY = 10;
    private Object[] elementData;
    private int size;

    // 확장: 약 1.5배 (oldCapacity + oldCapacity >> 1)
    private void grow(int minCapacity) {
        int oldCapacity = elementData.length;
        int newCapacity = oldCapacity + (oldCapacity >> 1);  // 1.5배

        if (newCapacity < minCapacity)
            newCapacity = minCapacity;

        elementData = Arrays.copyOf(elementData, newCapacity);
    }

    // 삽입 위치 지정 시 arraycopy로 이동
    public void add(int index, E element) {
        ensureCapacityInternal(size + 1);
        System.arraycopy(elementData, index,
                        elementData, index + 1,
                        size - index);
        elementData[index] = element;
        size++;
    }
}
```

### C++ std::vector

```cpp
// C++ vector의 핵심 동작
template<typename T>
class vector {
private:
    T* data;
    size_t size_;
    size_t capacity_;

public:
    // push_back: amortized O(1)
    void push_back(const T& value) {
        if (size_ == capacity_) {
            // 확장: 보통 2배
            size_t new_capacity = (capacity_ == 0) ? 1 : capacity_ * 2;
            reserve(new_capacity);
        }
        data[size_++] = value;
    }

    // reserve: 미리 용량 확보
    void reserve(size_t new_capacity) {
        if (new_capacity > capacity_) {
            T* new_data = new T[new_capacity];
            std::copy(data, data + size_, new_data);
            delete[] data;
            data = new_data;
            capacity_ = new_capacity;
        }
    }

    // shrink_to_fit: 남는 공간 제거 (C++11)
    void shrink_to_fit() {
        if (size_ < capacity_) {
            T* new_data = new T[size_];
            std::copy(data, data + size_, new_data);
            delete[] data;
            data = new_data;
            capacity_ = size_;
        }
    }
};
```

## 연산별 시간 복잡도

- 연산: get(i):
  - 평균: O(1)
  - 최악: O(1)
  - 비고: 인덱스 접근
- 연산: set(i, e):
  - 평균: O(1)
  - 최악: O(1)
  - 비고: 인덱스 접근
- 연산: add(e) (끝):
  - 평균: O(1) amortized
  - 최악: O(n)
  - 비고: 확장 시
- 연산: add(i, e):
  - 평균: O(n)
  - 최악: O(n)
  - 비고: 원소 이동
- 연산: remove(끝):
  - 평균: O(1)
  - 최악: O(1)
- 연산: remove(i):
  - 평균: O(n)
  - 최악: O(n)
  - 비고: 원소 이동
- 연산: contains(e):
  - 평균: O(n)
  - 최악: O(n)
  - 비고: 선형 탐색
