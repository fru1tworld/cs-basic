# 해시 테이블

해시 테이블은 키를 해시 함수로 변환해 저장할 위치를 찾는다. 키와 값을 쌍으로 보관하며 검색·삽입·삭제의 평균 비용은 O(1)이다. 다만 서로 다른 키가 같은 위치를 가리킬 수 있으므로, 충돌이 발생했을 때 저장하고 찾는 방법이 필요하다.

## 핵심 자료구조

### Hash Table (해시 테이블)

예를 들어 `apple`과 `grape`가 모두 3번 위치에 대응하면, 체이닝 방식은 같은 버킷에서 두 항목을 연결한다.

| 인덱스 | 저장된 항목 |
| --- | --- |
| 0 | 비어 있음 |
| 1 | (banana, 2) |
| 2 | 비어 있음 |
| 3 | (apple, 5), (grape, 8) |
| 4 | (orange, 3) |

- 연산: 삽입:
  - 평균: O(1)
  - 최악: O(n)
- 연산: 삭제:
  - 평균: O(1)
  - 최악: O(n)
- 연산: 탐색:
  - 평균: O(1)
  - 최악: O(n)

```java
// Java HashMap 내부 동작
public class HashMapExample {
    public static void main(String[] args) {
        Map<String, Integer> map = new HashMap<>();

        // O(1) 평균
        map.put("apple", 5);    // hash("apple") % capacity
        map.put("banana", 3);
        map.get("apple");       // 5

        // Java 8+: 버킷 크기가 8 이상이면 Red-Black Tree로 변환
        // → 최악 O(log n)으로 개선

        // Load Factor: 0.75 (기본값)
        // 용량의 75% 찼을 때 2배로 확장 (rehashing)
    }
}

// 충돌 해결 방법
// 1. Chaining: 연결 리스트로 연결
// 2. Open Addressing: 다른 빈 슬롯 탐색
//    - Linear Probing: 순차 탐색
//    - Quadratic Probing: 제곱 간격 탐색
//    - Double Hashing: 두 번째 해시 함수 사용
```

```python
# Python - 해시 테이블 활용
from collections import Counter, defaultdict

# 빈도수 계산
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]
counter = Counter(words)
print(counter.most_common(2))  # [('apple', 3), ('banana', 2)]

# 그룹화
from itertools import groupby

def group_anagrams(strs):
    anagrams = defaultdict(list)
    for s in strs:
        key = tuple(sorted(s))  # 정렬된 문자열을 키로
        anagrams[key].append(s)
    return list(anagrams.values())

# Two Sum 문제 - O(n)
def two_sum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []
```

## 해시 테이블 구조

키를 해시 함수에 넣어 인덱스를 정하면, 그 인덱스의 버킷에 값을 저장한다. `apple`의 인덱스가 3이면 `bucket[3]`을 사용한다. 예를 들어 1번에는 `banana: 50`, 3번에는 `apple: 100`, 4번에는 `cherry: 30`이 들어 있고 나머지 버킷은 비어 있을 수 있다.

## 해시 함수 (Hash Function)

해시 함수는 크기가 다양한 입력을 고정된 크기의 값으로 매핑한다. 해시 테이블에서는 이 값으로 저장 위치를 결정하므로, 분포와 계산 비용이 조회 성능에 영향을 준다.

### 좋은 해시 함수 조건

- 결정적: 같은 입력 → 항상 같은 출력
- 균등 분포: 출력이 골고루 분포
- 빠른 계산: O(1) 시간
- 최소 충돌: 다른 입력 → 다른 출력 (이상적)

### 해시 함수 예시

- 나눗셈법 (Division Method):
- h(k) = k mod m, (m은 테이블 크기, 주로 소수)
- 예: m = 13
- h(15) = 15 mod 13 = 2
- h(28) = 28 mod 13 = 2, ← 충돌!

- 곱셈법 (Multiplication Method):
- h(k) = floor(m × (k × A mod 1))
- A는 0 < A < 1인 상수 (황금비 권장: 0.6180339...)

- 문자열 해시:

```java
// Java String.hashCode()
int hash = 0;
for (char c : str) {
    hash = 31 * hash + c;
}
```

## 해시 충돌 (Collision)

서로 다른 키가 같은 인덱스에 대응하는 것을 충돌이라고 한다. 앞의 예처럼 `apple`과 `grape`가 모두 3으로 매핑되는 경우다. 가능한 키의 수가 버킷 수보다 많으면 비둘기집 원리에 따라 충돌을 완전히 없앨 수 없다.

## 충돌 해결 방법

### 체이닝 (Chaining)

체이닝은 같은 인덱스의 항목들을 연결 리스트로 묶는다. 3번 버킷에 `apple: 100`이 있을 때 `grape: 70`도 3번으로 매핑되면, 같은 리스트에 추가하고 조회할 때 키를 비교한다. 다른 버킷의 `banana: 50`, `cherry: 30`과는 별도의 리스트다.

- 장점:
- 구현 간단
- 삭제 쉬움
- 적재율 > 1 가능

- 단점:
- 추가 메모리 (포인터)
- 캐시 효율 낮음 (메모리 불연속)

- 시간 복잡도:
- 평균: O(1 + α) (α = 적재율 = n/m)
- 최악: O(n) (모든 키가 같은 버킷)

### 개방 주소법 (Open Addressing)

개방 주소법은 항목을 별도 리스트로 연결하지 않고 테이블 안의 다른 빈자리를 찾는다. 충돌했을 때 다음으로 어느 위치를 확인할지에 따라 탐사 방식이 나뉜다.

- 선형 탐사 (Linear Probing):
- h(k, i) = (h(k) + i) mod m
- 충돌 시 다음 칸으로 이동:
- h(k), h(k)+1, h(k)+2, ...
- 예: hash("apple") = 3, hash("grape") = 3
- 0, 1, 2, apple, grape, 5
- index=3, index=4

- 문제: 클러스터링 (연속된 데이터 뭉침)

- 이차 탐사 (Quadratic Probing):
- h(k, i) = (h(k) + i²) mod m
- 충돌 시: h(k), h(k)+1, h(k)+4, h(k)+9, ...

- 이중 해싱 (Double Hashing):
- h(k, i) = (h1(k) + i × h2(k)) mod m
- 두 번째 해시 함수로 탐사 간격 결정
- → 클러스터링 감소

삭제할 때는 탐사 경로를 끊지 않아야 한다. A와 B가 모두 3번에 대응해 B를 4번에 저장했다고 하자. A를 지우고 3번을 한 번도 사용하지 않은 빈칸처럼 취급하면, B를 찾는 중에 3번에서 탐색을 끝낼 수 있다. 따라서 삭제 표시(DELETED)를 남겨 뒤쪽 탐사를 계속할 수 있게 한다.

## 적재율 (Load Factor)

- α = n / m
- n: 저장된 요소 수
- m: 버킷 수

적재율이 높아지면 충돌이 늘어 성능이 떨어지므로, 일반적으로 0.7~0.75 정도를 기준으로 용량을 관리한다. 임계값을 넘었을 때 테이블을 늘리고 항목을 다시 배치하는 작업을 리해싱(Rehashing)이라고 한다. 예를 들어 α가 0.75를 넘으면 버킷 수를 4개에서 8개로 늘리고 각 키의 위치를 다시 계산할 수 있다.

## 시간 복잡도

- 연산: 검색:
  - 평균: O(1)
  - 최악: O(n)
- 연산: 삽입:
  - 평균: O(1)
  - 최악: O(n)
- 연산: 삭제:
  - 평균: O(1)
  - 최악: O(n)

- 최악의 경우: 모든 키가 같은 버킷으로 해싱 (해시 함수 품질 낮음)

## 해시 테이블 vs 다른 자료구조

- : 검색:
  - 해시 테이블: O(1)
  - 이진 탐색 트리: O(log n)
  - 배열: O(n)
- : 삽입:
  - 해시 테이블: O(1)
  - 이진 탐색 트리: O(log n)
  - 배열: O(n)
- : 삭제:
  - 해시 테이블: O(1)
  - 이진 탐색 트리: O(log n)
  - 배열: O(n)
- : 순서 유지:
  - 해시 테이블: X
  - 이진 탐색 트리: O
  - 배열: 인덱스 순
- : 범위 검색:
  - 해시 테이블: X
  - 이진 탐색 트리: O
  - 배열: O
- : 메모리:
  - 해시 테이블: 추가 필요
  - 이진 탐색 트리: 추가 필요
  - 배열: 연속
