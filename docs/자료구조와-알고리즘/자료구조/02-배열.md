# 배열

배열(Array)은 같은 타입의 원소를 연속된 메모리 공간에 저장한다. 원소의 크기와 시작 주소를 알면 인덱스로 위치를 계산할 수 있어 O(1) 임의 접근이 가능하다. 연속된 원소를 차례로 읽는 방식은 캐시 지역성을 활용하는 데도 유리하다.

## 핵심 자료구조

### Array (배열)

예를 들어 A부터 H까지 여덟 원소를 저장하면 각각 인덱스 0부터 7에 대응한다. 각 원소는 배열의 시작 주소(Base Address)에서 일정한 간격으로 놓인다.

- 연산: 인덱스 접근:
  - 시간 복잡도: O(1)
- 연산: 맨 끝 삽입/삭제:
  - 시간 복잡도: O(1)
- 연산: 중간 삽입/삭제:
  - 시간 복잡도: O(n)
- 연산: 탐색 (정렬 X):
  - 시간 복잡도: O(n)
- 연산: 탐색 (정렬 O):
  - 시간 복잡도: O(log n)

```java
// Java - 배열 vs ArrayList
public class ArrayExample {
    public static void main(String[] args) {
        // 정적 배열
        int[] staticArray = new int[5];
        staticArray[0] = 10;

        // 동적 배열 (ArrayList)
        ArrayList<Integer> dynamicArray = new ArrayList<>();
        dynamicArray.add(10);  // O(1) amortized
        dynamicArray.get(0);   // O(1)
        dynamicArray.add(0, 5); // O(n) - 맨 앞 삽입
    }
}
```

## 메모리 레이아웃

원소 크기가 4바이트이고 시작 주소가 0x1000이면, 인덱스 0부터 7의 주소는 0x1000, 0x1004, 0x1008, 0x100C, 0x1010, 0x1014, 0x1018, 0x101C가 된다. 값이 10, 20, 30, 40, 50, 60, 70, 80일 때도 위치 간격은 값과 무관하게 4바이트다.

이를 일반화하면 `address(arr[i]) = base_address + i × element_size`다.

```java
// Java에서 배열 선언과 메모리
int[] arr = new int[8];

// arr 변수: 배열 객체의 참조(주소)를 저장
// 실제 배열: 힙 메모리에 연속적으로 할당
// 각 int: 4바이트, 총 32바이트 + 객체 헤더
```

## Random Access (임의 접근)

인덱스 접근은 앞의 원소를 하나씩 거치지 않고 주소를 계산한다. 따라서 첫 원소를 읽을 때와 마지막 원소를 읽을 때의 주소 계산 비용이 입력 크기에 따라 달라지지 않는다.

```java
// O(1) 접근 - 인덱스로 바로 계산
int value = arr[5];  // base + 5 * 4 = 즉시 주소 계산

// vs 연결 리스트의 O(n) 접근
// head → node → node → node → node → node (5번 이동)
```

고정된 원소 크기와 연속된 배치 덕분에 필요한 계산은 곱셈과 덧셈으로 끝난다. 연결 리스트에서 다음 노드를 따라가는 방식과 차이가 나는 지점이다.

## Cache Locality (캐시 지역성)

CPU는 메모리에 접근할 때 캐시 라인 단위로 데이터를 가져온다. 보통 64바이트인 이 단위 안에 인접한 배열 원소가 함께 들어가므로, 연속해서 순회할 때 이미 가져온 데이터를 재사용할 수 있다.

- 캐시 라인 로드 예시 (64바이트 캐시 라인, int 배열):
- arr[0] 접근 시:
- arr[0] ~ arr[15] 까지 16개의 int가 캐시에 로드됨
- 이후 arr[1] ~ arr[15] 접근은 캐시 히트 (매우 빠름)

```java
// 캐시 친화적인 순회 (순차 접근)
// 캐시 히트율 높음
int sum = 0;
for (int i = 0; i < arr.length; i++) {
    sum += arr[i];  // 순차 접근
}

// 캐시 비친화적인 순회 (점프 접근)
// 캐시 미스율 높음
int sum = 0;
for (int i = 0; i < arr.length; i += 64) {
    sum += arr[i];  // 큰 간격으로 점프
}
```

- 성능 차이 예시:
- 순차 접근: ~1 ns/element (캐시 히트)
- 랜덤 접근: ~100 ns/element (메인 메모리 접근)
- → 최대 100배 차이

## Row-major vs Column-major Order

- 다차원 배열을 1차원 메모리에 저장하는 두 가지 방식:

- 2D 배열:
- col 0, col 1, col 2
- row 0, [1], [2], [3]
- row 1, [4], [5], [6]
- Row-major (행 우선): C, C++, Java, Python
- 메모리: [1][2][3][4][5][6]
- 순서: (0,0) → (0,1) → (0,2) → (1,0) → (1,1) → (1,2)
- Column-major (열 우선): Fortran, MATLAB, R
- 메모리: [1][4][2][5][3][6]
- 순서: (0,0) → (1,0) → (0,1) → (1,1) → (0,2) → (1,2)

- Row-major 주소 계산:
- address(arr[i][j]) = base + (i × cols + j) × element_size
- 예: arr[1][2], cols=3, element_size=4
- address = base + (1 × 3 + 2) × 4 = base + 20

저장 순서와 순회 순서를 맞추면 이웃한 원소를 연속해서 읽을 수 있다. 다음 코드는 행을 먼저 도는 경우와 열을 먼저 도는 경우를 비교한다.

```java
// Row-major에서 캐시 효율적인 순회
// 행을 따라 순회 (메모리 순서와 일치)
for (int i = 0; i < rows; i++) {
    for (int j = 0; j < cols; j++) {
        process(matrix[i][j]);  // 캐시 히트
    }
}

// 비효율적인 순회 (열을 따라)
// 메모리 점프가 발생
for (int j = 0; j < cols; j++) {
    for (int i = 0; i < rows; i++) {
        process(matrix[i][j]);  // 캐시 미스 많음
    }
}
```

## 배열의 연산과 복잡도

인덱스로 위치를 찾는 비용과 원소를 삽입·삭제하는 비용은 다르다. 배열 중간에 빈자리를 만들거나 메우려면 뒤쪽 원소를 이동해야 하기 때문이다.

- 연산: 접근 (Access):
  - 시간 복잡도: O(1)
  - 설명: 인덱스로 직접 접근
- 연산: 검색 (Search):
  - 시간 복잡도: O(n)
  - 설명: 선형 탐색 (정렬 시 O(log n))
- 연산: 삽입 (끝):
  - 시간 복잡도: O(1)
  - 설명: 크기가 충분한 경우
- 연산: 삽입 (중간):
  - 시간 복잡도: O(n)
  - 설명: 뒤의 원소들 이동 필요
- 연산: 삭제 (끝):
  - 시간 복잡도: O(1)
- 연산: 삭제 (중간):
  - 시간 복잡도: O(n)
  - 설명: 뒤의 원소들 이동 필요

```java
// 중간 삽입의 비용
void insertAt(int[] arr, int index, int value, int size) {
    // index부터 끝까지 모든 원소를 한 칸씩 뒤로 이동
    for (int i = size - 1; i >= index; i--) {
        arr[i + 1] = arr[i];  // O(n - index) 연산
    }
    arr[index] = value;
}

// 중간 삭제의 비용
void removeAt(int[] arr, int index, int size) {
    // index+1부터 끝까지 모든 원소를 한 칸씩 앞으로 이동
    for (int i = index; i < size - 1; i++) {
        arr[i] = arr[i + 1];  // O(n - index) 연산
    }
}
```

## 배열 vs 연결 리스트

- 특성: 메모리:
  - 배열: 연속적
  - 연결 리스트: 분산
- 특성: 접근:
  - 배열: O(1)
  - 연결 리스트: O(n)
- 특성: 삽입/삭제 (중간):
  - 배열: O(n)
  - 연결 리스트: O(1)\*
- 특성: 메모리 오버헤드:
  - 배열: 없음
  - 연결 리스트: 포인터 공간
- 특성: 캐시 효율:
  - 배열: 높음
  - 연결 리스트: 낮음
- 특성: 크기 변경:
  - 배열: 비용 큼
  - 연결 리스트: 쉬움

- \*위치를 알고 있는 경우
