# 분할 상환 분석

어떤 연산은 대부분 빠르게 끝나지만 가끔 큰 비용을 낸다. 동적 배열에서 공간이 부족할 때 모든 원소를 복사하는 경우가 그렇다. 분할 상환 분석은 이런 연산을 한 번씩 떼어 보는 대신 일련의 연산이 지불하는 총비용을 구하고, 이를 연산 수로 나누어 한 번당 비용을 분석한다.

## 평균 케이스 분석과의 차이

평균 케이스 분석은 입력의 확률 분포를 가정해 기대 비용을 구한다. 반면 분할 상환 분석은 확률을 가정하지 않고, 연산 시퀀스의 최악 비용을 전체 연산에 나누어 상한을 구한다. 여기서 말하는 평균은 입력에 대한 기대값이 아니다.

## 세 가지 분석 방법

- Aggregate Method (총합 분석)
- Accounting Method (회계 분석)
- Potential Method (포텐셜 분석)

## Aggregate Method (총합 분석)

총합 분석은 n개 연산의 총비용 T(n)을 먼저 구한 뒤 T(n)/n을 계산한다. 개별 연산의 비용이 달라도 합계에 일정한 상한을 줄 수 있으면 된다.

### 예시: 동적 배열의 삽입

아래 동적 배열은 용량이 가득 차면 두 배로 확장한다. 확장할 때 복사하는 원소 수가 어떻게 늘어나는지 세면 총비용을 구할 수 있다.

```java
class DynamicArray {
    private int[] array;
    private int size;
    private int capacity;

    public DynamicArray() {
        capacity = 1;
        array = new int[capacity];
        size = 0;
    }

    // 배열이 가득 차면 2배로 확장
    public void add(int element) {
        if (size == capacity) {
            // 확장: O(n) 비용
            capacity *= 2;
            int[] newArray = new int[capacity];
            for (int i = 0; i < size; i++) {
                newArray[i] = array[i];
            }
            array = newArray;
        }
        array[size++] = element;  // O(1) 비용
    }
}
```

확장 시 복사하는 원소 수는 1, 2, 4, 8처럼 늘어난다. `2^k ≤ n < 2^(k+1)`인 k를 잡으면 복사 비용의 합은 `1 + 2 + ... + 2^k = 2^(k+1) - 1 < 2n`으로 제한할 수 있다. 일반 삽입 n번의 비용을 더해도 총비용은 `T(n) < 3n`이므로, 한 번당 분할 상환 비용은 O(1)이다.

### 예시: 이진 카운터 증가

이진 카운터에서도 한 번의 증가가 여러 비트를 뒤집을 수 있다. 다만 높은 자리의 비트일수록 드물게 바뀌므로, 자리별 변경 횟수를 합산해서 분석한다.

```java
class BinaryCounter {
    private int[] bits;  // bits[0]이 LSB

    public BinaryCounter(int k) {
        bits = new int[k];  // k비트 카운터
    }

    // 1 증가
    public void increment() {
        int i = 0;
        while (i < bits.length && bits[i] == 1) {
            bits[i] = 0;  // flip
            i++;
        }
        if (i < bits.length) {
            bits[i] = 1;  // flip
        }
    }
}
```

- 분석:
- n번의 increment 연산에서 각 비트가 flip되는 횟수:
- bits[0]: 매번 flip → n번
- bits[1]: 2번에 1번 flip → n/2번
- bits[2]: 4번에 1번 flip → n/4번
- bits[k-1]: 최대 n/2^(k-1)번
- 총 flip 횟수 = n + n/2 + n/4 + ... < 2n
- 분할 상환 비용 = T(n)/n < 2 = O(1)

## Accounting Method (회계 분석)

회계 분석은 각 연산에 상환 비용(amortized cost)을 배정한다. 실제 비용보다 많이 배정한 몫은 크레딧으로 남겨 두고, 나중에 비싼 연산이 발생했을 때 사용한다. 어떤 시점에도 크레딧이 부족하지 않도록 정하면, 배정한 비용의 합으로 실제 비용을 감당할 수 있다.

- 규칙:
- 상환 비용 ≥ 실제 비용의 합 (항상)
- 크레딧은 음수가 되면 안 됨

### 예시: 동적 배열의 삽입

- 연산별 비용 설정:
- 삽입 1회당 상환 비용: 3 단위
- 비용 분배:
- 실제 삽입: 1 단위 (즉시 사용)
- 나중 복사를 위한 크레딧: 2 단위 (저축)
- 자신을 복사할 비용: 1 단위
- 이전 원소의 복사 도움: 1 단위
- 검증:
- 확장 시점에 원소 수가 k → 2k로 증가
- k개 원소 복사 비용 = k
- 저축된 크레딧 = 이전 확장 이후 삽입된 k/2개 × 2 = k
- 크레딧으로 정확히 복사 비용 지불 가능

예를 들어 용량 4인 배열에 원소 1, 2, 3, 4가 들어 있다면, 원소 3과 4를 삽입하면서 남긴 크레딧은 각각 2다. 용량을 8로 늘릴 때는 이 크레딧 4로 기존 원소 네 개를 복사한다. 이후 원소 5부터 8까지 삽입하며 다음 확장에 쓸 크레딧을 다시 쌓는다.

### 예시: 스택의 MultiPop

한 번에 여러 원소를 제거하는 `multiPop`은 호출 한 번의 비용이 클 수 있다. 하지만 제거할 원소는 앞서 삽입한 원소이므로, `push`할 때 제거 비용까지 미리 배정하는 방식으로 분석할 수 있다.

```java
class AmortizedStack {
    private Stack<Integer> stack = new Stack<>();

    // O(1) 실제 비용
    public void push(int x) {
        stack.push(x);
    }

    // O(1) 실제 비용
    public int pop() {
        return stack.pop();
    }

    // O(k) 실제 비용 (k = min(k, size))
    public void multiPop(int k) {
        while (!stack.isEmpty() && k > 0) {
            stack.pop();
            k--;
        }
    }
}
```

- 회계 분석:
- 상환 비용 할당:
- push: 2 (실제 1 + 나중 pop을 위한 크레딧 1)
- pop: 0 (크레딧 사용)
- multiPop(k): 0 (크레딧 사용)
- 검증:
- 각 원소는 push될 때 2를 지불
- pop/multiPop에서 pop당 1의 크레딧 사용
- 원소는 최대 1번만 pop되므로 크레딧 충분
- n개 연산의 총 상환 비용 ≤ 2n (push가 최대 n번)
- 분할 상환 비용 = O(1)

## Potential Method (포텐셜 분석)

포텐셜 분석은 개별 원소의 크레딧 대신 자료구조 전체의 상태에 포텐셜 Φ를 부여한다. 연산의 실제 비용에 포텐셜 변화량을 더한 값을 상환 비용으로 정한다.

- ĉᵢ = cᵢ + Φ(Dᵢ) - Φ(Dᵢ₋₁)
- 여기서:
- ĉᵢ: i번째 연산의 상환 비용
- cᵢ: i번째 연산의 실제 비용
- Φ(Dᵢ): i번째 연산 후 자료구조의 포텐셜
- Φ(D₀) = 0 (초기 포텐셜)
- Φ(Dᵢ) ≥ 0 (모든 i에 대해)

이 식을 연산 전체에 대해 더하면 중간 상태의 포텐셜이 상쇄된다. 초기 포텐셜이 0이고 마지막 포텐셜이 음수가 아니면, 총 상환 비용이 실제 비용의 상한이 된다.

- Σĉᵢ = Σcᵢ + Φ(Dₙ) - Φ(D₀)
- = Σcᵢ + Φ(Dₙ), (Φ(D₀) = 0이므로)
- ≥ Σcᵢ, (Φ(Dₙ) ≥ 0이므로)

### 예시: 동적 배열

- 포텐셜 함수 정의:
- Φ(D) = 2 × size - capacity
- 검증:
- 확장 직전: size = capacity = n
- Φ = 2n - n = n
- 확장 직후: size = n, capacity = 2n
- Φ = 2n - 2n = 0
- 일반 삽입의 상환 비용:
- ĉ = 1 + (2(size+1) - capacity) - (2×size - capacity)
- = 1 + 2 = 3
- 확장 삽입의 상환 비용:
- ĉ = (1 + n) + (2(n+1) - 2n) - (2n - n)
- = n + 1 + 2 - n = 3
- 모든 삽입의 상환 비용 = O(1)

### 예시: Splay Tree의 Splay 연산

- 포텐셜 함수 정의:
- Φ(T) = Σ rank(x), (모든 노드 x에 대해)
- 여기서 rank(x) = log(size(x))
- size(x) = x를 루트로 하는 서브트리의 노드 수
- Access Lemma:
- splay(x)의 상환 비용 ≤ 3(rank(root) - rank(x)) + 1
- = O(log n)
- 증명은 Zig, Zig-Zig, Zig-Zag 각 케이스 분석으로 진행
- (상세 증명은 CLRS 17장 참조)

## 분석 방법 비교

- 방법: Aggregate:
  - 장점: 직관적, 단순
  - 단점: 개별 연산 비용 구분 어려움
  - 적합한 경우: 모든 연산이 동일한 경우
- 방법: Accounting:
  - 장점: 개별 연산 분석 가능
  - 단점: 적절한 크레딧 설정 필요
  - 적합한 경우: 직관적으로 "저축" 설명 가능한 경우
- 방법: Potential:
  - 장점: 가장 일반적, 강력
  - 단점: 포텐셜 함수 설계 어려움
  - 적합한 경우: 복잡한 자료구조 분석
