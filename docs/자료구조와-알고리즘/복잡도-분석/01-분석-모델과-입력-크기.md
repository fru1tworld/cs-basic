# 분석 모델과 입력 크기

알고리즘이 작은 입력에서 빠르게 동작하더라도 입력이 커졌을 때 같은 방식으로 처리할 수 있는지는 별개의 문제다. 이를 비교하기 위해 사용하는 시간과 공간을 입력 크기의 함수로 표현한다. 이렇게 하면 입력이 늘어날 때 필요한 자원이 얼마나 빠르게 증가하는지 살펴볼 수 있다.

## 시간/공간 복잡도 분석

### 주요 시간 복잡도

- 복잡도: O(1):
  - 이름: 상수
  - 예시: 배열 인덱스 접근, 해시맵 조회
  - n=1,000일 때 연산 수: 1
- 복잡도: O(log n):
  - 이름: 로그
  - 예시: 이진 탐색, 균형 트리 연산
  - n=1,000일 때 연산 수: ~10
- 복잡도: O(n):
  - 이름: 선형
  - 예시: 배열 순회, 선형 탐색
  - n=1,000일 때 연산 수: 1,000
- 복잡도: O(n log n):
  - 이름: 선형 로그
  - 예시: 병합 정렬, 퀵 정렬 (평균)
  - n=1,000일 때 연산 수: ~10,000
- 복잡도: O(n²):
  - 이름: 이차
  - 예시: 버블 정렬, 이중 반복문
  - n=1,000일 때 연산 수: 1,000,000
- 복잡도: O(n³):
  - 이름: 삼차
  - 예시: 행렬 곱셈 (naive)
  - n=1,000일 때 연산 수: 1,000,000,000
- 복잡도: O(2^n):
  - 이름: 지수
  - 예시: 부분집합, 피보나치 (naive)
  - n=1,000일 때 연산 수: 천문학적
- 복잡도: O(n!):
  - 이름: 팩토리얼
  - 예시: 순열 생성, 외판원 (brute force)
  - n=1,000일 때 연산 수: 계산 불가

### 복잡도 분석 예제

다음 예제에서는 반복 횟수와 문제를 줄여 나가는 방식에 주목하면 된다. 배열의 첫 원소를 읽는 코드는 입력 크기에 영향을 받지 않지만, 순회와 정렬은 처리해야 할 원소 수에 따라 비용이 달라진다.

```python
# O(1) - 상수 시간
def get_first(arr):
    return arr[0] if arr else None

# O(log n) - 로그 시간
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

# O(n) - 선형 시간
def find_max(arr):
    max_val = arr[0]
    for num in arr:  # n번 반복
        if num > max_val:
            max_val = num
    return max_val

# O(n log n) - 선형 로그 시간
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])   # T(n/2)
    right = merge_sort(arr[mid:])  # T(n/2)
    return merge(left, right)      # O(n)
    # T(n) = 2T(n/2) + O(n) = O(n log n)

# O(n²) - 이차 시간
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):           # n번
        for j in range(n-i-1):   # n-i-1번
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
    return arr
```

```java
// O(2^n) - 지수 시간 (피보나치 naive)
public class Fibonacci {
    // 재귀 호출이 트리 형태로 증가
    public static int fibNaive(int n) {
        if (n <= 1) return n;
        return fibNaive(n - 1) + fibNaive(n - 2);
    }

    // O(n) - 동적 프로그래밍으로 최적화
    public static int fibDP(int n) {
        if (n <= 1) return n;
        int[] dp = new int[n + 1];
        dp[0] = 0;
        dp[1] = 1;
        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i-1] + dp[i-2];
        }
        return dp[n];
    }
}
```

### Amortized Analysis (분할 상환 분석)

모든 연산이 매번 같은 비용을 갖는 것은 아니다. 다음 동적 배열은 공간이 남아 있으면 바로 삽입하지만, 가득 차면 기존 원소를 새 배열로 복사한다. 분할 상환 분석은 이처럼 드물게 발생하는 큰 비용을 연산 전체에 나누어 계산한다.

```java
// ArrayList의 add 연산
// 최악: O(n) - 배열 확장 시
// 평균(분할 상환): O(1)

public class DynamicArray<T> {
    private Object[] data;
    private int size;
    private int capacity;

    public DynamicArray() {
        this.capacity = 10;
        this.data = new Object[capacity];
        this.size = 0;
    }

    // 분할 상환 O(1)
    public void add(T element) {
        if (size == capacity) {
            // O(n) - 가끔 발생
            resize();
        }
        data[size++] = element;  // O(1)
    }

    private void resize() {
        capacity *= 2;  // 2배로 확장
        Object[] newData = new Object[capacity];
        System.arraycopy(data, 0, newData, 0, size);
        data = newData;
    }

    // n개 삽입 시 총 비용:
    // n + (1 + 2 + 4 + 8 + ... + n) ≈ 3n
    // 따라서 평균: O(1)
}
```

## RAM 모델 (Random Access Machine)

연산 횟수를 세려면 무엇을 한 번의 연산으로 볼지 정해야 한다. RAM 모델은 알고리즘 분석을 위해 단순 연산과 메모리 접근을 상수 시간으로 취급하는 이론적 모델이다.

- 산술 연산 `+`, `-`, `*`, `/`, `%`, 비교 연산, 대입, 배열 인덱스 접근을 O(1)로 본다.
- 메모리 주소를 알면 일정한 시간에 접근한다고 가정하고 캐시 계층은 고려하지 않는다.
- 필요한 만큼 메모리를 사용할 수 있다고 가정한다.

이 가정 덕분에 분석은 단순해지지만, 실제 실행에서는 다음과 같은 차이가 생긴다.

```python
# 실제로는 다음 연산들의 비용이 다름

# 1. 캐시 효과 (연속 메모리 접근이 더 빠름)
for i in range(n):
    sum += arr[i]      # 캐시 친화적

for i in random_order:
    sum += arr[i]      # 캐시 비친화적

# 2. 큰 정수 연산 (자릿수에 비례)
x = 2 ** 1000         # O(1)이 아님
y = x * x             # 실제로는 O(k²) where k = 자릿수

# 3. 분기 예측 실패 비용
if random_condition:  # 분기 예측 실패 시 파이프라인 지연
    do_something()
```

## 입력 크기 정의

같은 n이라는 기호를 쓰더라도 무엇을 세는지는 문제마다 다르다. 그래프나 문자열 매칭처럼 입력을 나타내는 변수가 둘 이상 필요한 경우도 있다.

| 문제 | 입력 크기 |
| --- | --- |
| 배열 정렬 | 원소 수 |
| 행렬 곱셈 | n×n 행렬의 행·열 크기 |
| 그래프 알고리즘 | 정점 수 V와 간선 수 E |
| 문자열 매칭 | 텍스트 길이 n과 패턴 길이 m |
| 정수 연산 | 정수를 표현하는 비트 수, 약 log n |

특히 정수의 값과 그 값을 표현하는 비트 수를 구분해야 한다. 다음 소수 판정 예제는 어떤 값을 입력 크기로 삼느냐에 따라 복잡도의 표현이 달라지는 이유를 보여 준다.

```python
# 예: 소수 판정
def is_prime(n):
    """O(√n) vs O(√2^k) where k = bit length of n"""
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0:
            return False
    return True

# n = 10^18이면:
# - 입력 크기를 n으로 보면: O(√n) = O(10^9)
# - 입력 크기를 비트 수 k=60으로 보면: O(2^(k/2)) = O(2^30) - 지수 시간!
#
# 암호학에서는 비트 수 기준이 중요 (다항 시간 vs 지수 시간)
```

## 최선/평균/최악 케이스 분석

입력 크기가 같아도 데이터의 배치에 따라 실행 시간이 달라질 수 있다. 선형 탐색에서는 찾는 값이 어느 위치에 있는지가 비교 횟수를 결정한다.

```python
def linear_search(arr, target):
    """선형 탐색의 세 가지 케이스 분석"""
    for i, x in enumerate(arr):
        if x == target:
            return i
    return -1
```

- 세 가지 케이스:
- 최선 (Best):
  - 시간 복잡도: O(1)
  - 조건: target이 첫 번째 위치
- 평균 (Avg):
  - 시간 복잡도: O(n)
  - 조건: target이 균등 분포로 존재
- 최악 (Worst):
  - 시간 복잡도: O(n)
  - 조건: target이 마지막이거나 없음

퀵 정렬에서도 피벗이 입력을 어떻게 나누는지에 따라 비용이 달라진다. 다음 구현은 첫 원소를 피벗으로 선택한다.

```python
def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[0]  # 첫 원소를 피벗으로
    left = [x for x in arr[1:] if x < pivot]
    right = [x for x in arr[1:] if x >= pivot]
    return quicksort(left) + [pivot] + quicksort(right)
```

- 최선:
  - 시간 복잡도: O(n log n)
  - 조건: 피벗이 항상 중앙값
- 평균:
  - 시간 복잡도: O(n log n)
  - 조건: 랜덤 입력
- 최악:
  - 시간 복잡도: O(n²)
  - 조건: 이미 정렬된 배열

## 평균 케이스 분석

평균 실행 시간을 계산하려면 어떤 입력이 얼마나 자주 나타나는지 정해야 한다. 선형 탐색에서 찾는 값이 반드시 존재하고 모든 위치에 같은 확률로 놓인다고 가정하면, 기대 비교 횟수는 다음과 같이 계산된다.

```python
def average_case_linear_search(n):
    """
    가정: target이 배열에 있고, 모든 위치에 균등하게 분포

    기대 비교 횟수:
    E[비교 횟수] = Σ(i=1 to n) i × P(target이 i번째 위치)
                = Σ(i=1 to n) i × (1/n)
                = (1/n) × n(n+1)/2
                = (n+1)/2
                = O(n)
    """
    return (n + 1) / 2
```

삽입 정렬은 모든 순열이 같은 확률로 나타난다고 가정하고, 각 삽입에서 앞쪽으로 이동하는 비용을 합산한다.

```python
def insertion_sort_analysis(n):
    """
    가정: 모든 순열이 균등하게 발생

    i번째 삽입 시 평균 비교 횟수:
    - 최선: 1번 (이미 정렬된 위치)
    - 최악: i번 (맨 앞으로 이동)
    - 평균: (1 + 2 + ... + i) / i = (i+1)/2

    전체 평균:
    E[총 비교] = Σ(i=1 to n-1) (i+1)/2
              = (1/2) × Σ(i=2 to n) i
              = (1/2) × (n(n+1)/2 - 1)
              ≈ n²/4
              = O(n²)
    """
    return n * n / 4
```

## Adversarial Analysis (적대적 분석)

평균 분석과 달리 적대적 분석은 알고리즘에 가장 불리한 입력을 선택하는 적대자(adversary)를 가정한다. 다음 최댓값 탐색 예제에서는 비교할 때마다 후보가 얼마나 줄어드는지를 이용해 필요한 비교 횟수의 하한을 설명한다.

```python
def find_max_adversarial():
    """
    문제: n개 원소 중 최댓값 찾기

    적대자 전략:
    - 알고리즘이 어떤 비교를 하든, 적대자는 결과를 선택
    - 아직 '패배'하지 않은 원소를 최대한 유지

    정리: 최댓값을 찾으려면 최소 n-1번의 비교가 필요

    증명:
    - 최댓값은 한 번도 비교에서 진 적이 없어야 함
    - n-1개의 원소가 최소 1번씩 져야 함
    - 각 비교에서 최대 1개 원소가 짐
    → 최소 n-1번 비교 필요
    """
    pass

def find_min_max_adversarial(n):
    """
    문제: n개 원소 중 최솟값과 최댓값 동시에 찾기

    순진한 방법: 2n - 3번 비교
    - 최댓값 찾기: n-1번
    - 최솟값 찾기: n-2번 (최댓값 제외)

    최적 알고리즘: ⌈3n/2⌉ - 2번 비교
    - 쌍으로 비교하여 후보 분류
    """
    # 쌍 비교 알고리즘
    pairs = n // 2
    comparisons_for_pairs = pairs  # 각 쌍당 1번

    # 작은 것들 중 min, 큰 것들 중 max
    smaller_group = (pairs + n % 2)  # 홀수면 하나 추가
    larger_group = pairs

    min_comparisons = smaller_group - 1
    max_comparisons = larger_group - 1

    total = comparisons_for_pairs + min_comparisons + max_comparisons
    # = n//2 + (n//2 + n%2 - 1) + (n//2 - 1)
    # = 3n//2 - 2 (n이 짝수일 때)
    # = 3(n-1)//2 (n이 홀수일 때)
    return total
```
