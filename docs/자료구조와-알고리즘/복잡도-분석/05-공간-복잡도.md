# 공간 복잡도

입력이 커지면 실행 시간뿐 아니라 필요한 메모리도 늘어날 수 있다. 공간 복잡도는 이 메모리 사용량을 입력 크기의 함수로 표현한다. 메모리 제한이 있거나 큰 데이터를 처리할 때는 실행 시간이 충분히 짧아도 필요한 공간을 확보할 수 있는지 확인해야 한다.

## 시간/공간 복잡도 분석

### 공간 복잡도

다음 예제는 별도의 배열을 만드는 경우와 호출 스택을 사용하는 경우를 비교한다. 반복문에서 변수 몇 개만 유지할 때와 달리, 새 배열이나 동시에 유지되는 재귀 호출은 입력에 따라 공간이 늘어난다.

```python
# O(1) 공간 - 상수 공간
def sum_array(arr):
    total = 0  # 변수 1개만 사용
    for num in arr:
        total += num
    return total

# O(n) 공간 - 선형 공간
def reverse_array(arr):
    result = []  # 입력 크기만큼 새 배열
    for i in range(len(arr) - 1, -1, -1):
        result.append(arr[i])
    return result

# O(n) 공간 - 재귀 호출 스택
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)  # 호출 스택 깊이 = n

# O(log n) 공간 - 이진 탐색 재귀
def binary_search_recursive(arr, target, left, right):
    if left > right:
        return -1
    mid = (left + right) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search_recursive(arr, target, mid + 1, right)
    else:
        return binary_search_recursive(arr, target, left, mid - 1)
```

## Auxiliary Space vs Total Space

공간을 계산할 때는 입력 자체가 차지하는 공간(Input Space)과 실행 중 추가로 사용하는 공간(Auxiliary Space)을 구분한다. 보조 공간에는 임시 변수와 자료구조 등이 포함되며, 두 공간을 합한 값이 전체 공간(Total Space)이다.

### 예시: 배열 정렬

```java
// Merge Sort
// Input Space: O(n) - 입력 배열
// Auxiliary Space: O(n) - 임시 배열
// Total Space: O(n) + O(n) = O(n)
void mergeSort(int[] arr, int[] temp, int left, int right) {
    if (left < right) {
        int mid = (left + right) / 2;
        mergeSort(arr, temp, left, mid);
        mergeSort(arr, temp, mid + 1, right);
        merge(arr, temp, left, mid, right);
    }
}

// Quick Sort (in-place)
// Input Space: O(n)
// Auxiliary Space: O(log n) - 재귀 스택
// Total Space: O(n) + O(log n) = O(n)
void quickSort(int[] arr, int low, int high) {
    if (low < high) {
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}

// Heap Sort (in-place)
// Input Space: O(n)
// Auxiliary Space: O(1) - 상수 개의 변수만 사용
// Total Space: O(n) + O(1) = O(n)
void heapSort(int[] arr) {
    int n = arr.length;
    for (int i = n / 2 - 1; i >= 0; i--)
        heapify(arr, n, i);
    for (int i = n - 1; i > 0; i--) {
        swap(arr, 0, i);
        heapify(arr, i, 0);
    }
}
```

## In-place Algorithm

여기서는 보조 공간이 O(1)이거나 재귀 스택 등을 포함해 O(log n)인 알고리즘을 in-place로 다룬다. 다음 버블 정렬은 입력 배열의 원소를 직접 교환하지만, 카운팅 정렬 예제는 빈도와 출력을 저장할 배열을 별도로 만든다.

```java
// In-place: 버블 정렬
// Auxiliary Space: O(1)
void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                // 임시 변수 1개만 사용
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

// Not in-place: 카운팅 정렬
// Auxiliary Space: O(k) where k = 값의 범위
int[] countingSort(int[] arr, int k) {
    int[] count = new int[k + 1];  // O(k) 추가 공간
    int[] output = new int[arr.length];  // O(n) 추가 공간

    for (int x : arr) count[x]++;
    for (int i = 1; i <= k; i++) count[i] += count[i-1];
    for (int i = arr.length - 1; i >= 0; i--) {
        output[count[arr[i]] - 1] = arr[i];
        count[arr[i]]--;
    }
    return output;
}
```

## 재귀와 공간 복잡도

재귀에서는 배열을 만들지 않더라도 호출 스택이 쌓인다. 공간을 계산할 때는 총호출 횟수와 동시에 남아 있는 호출의 깊이를 구분해야 한다. 피보나치 예제로 재귀, 반복, 메모이제이션의 차이를 살펴보자.

```java
// 피보나치 - 재귀 (비효율적)
// 시간: O(2^n)
// 공간: O(n) - 최대 재귀 깊이
int fibRecursive(int n) {
    if (n <= 1) return n;
    return fibRecursive(n - 1) + fibRecursive(n - 2);
}

// 피보나치 - 반복 (효율적)
// 시간: O(n)
// 공간: O(1)
int fibIterative(int n) {
    if (n <= 1) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}

// 피보나치 - 메모이제이션
// 시간: O(n)
// 공간: O(n) - 메모 배열 + 재귀 스택
int[] memo;
int fibMemo(int n) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];
    memo[n] = fibMemo(n - 1) + fibMemo(n - 2);
    return memo[n];
}
```

## 꼬리 재귀 최적화 (Tail Call Optimization)

재귀 호출 뒤에 수행할 연산이 남아 있는지도 중요하다. 일반 팩토리얼은 호출이 돌아온 뒤 곱셈을 해야 하지만, 누적값을 넘기는 꼬리 재귀는 호출 결과를 그대로 반환한다. 아래 공간 비교는 꼬리 호출 최적화가 적용되는 경우를 전제로 한다.

```java
// 일반 재귀: O(n) 스택 공간
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);  // 곱셈이 대기 중
}

// 꼬리 재귀: 최적화 시 O(1) 스택 공간
int factorialTail(int n, int acc) {
    if (n <= 1) return acc;
    return factorialTail(n - 1, n * acc);  // 대기 연산 없음
}

// 참고: Java는 TCO를 지원하지 않음
// Kotlin, Scala, Scheme 등은 지원
```

## Space-Time Tradeoff

중간 결과나 탐색용 자료구조를 저장하면 같은 계산을 반복하지 않아도 된다. 대신 그 결과를 보관할 공간이 필요하다. 다음 예제들은 시간을 줄이기 위해 어떤 메모리를 추가로 사용하는지 비교한다.

### 예시 1: 해시 테이블 vs 선형 탐색

```java
// 선형 탐색: O(1) 공간, O(n) 시간
boolean containsLinear(int[] arr, int target) {
    for (int x : arr) {
        if (x == target) return true;
    }
    return false;
}

// 해시 셋: O(n) 공간, O(1) 평균 시간
class FastLookup {
    private Set<Integer> set = new HashSet<>();

    void preprocess(int[] arr) {
        for (int x : arr) set.add(x);  // O(n) 공간 사용
    }

    boolean contains(int target) {
        return set.contains(target);  // O(1) 시간
    }
}
```

### 예시 2: 메모이제이션 vs 재계산

```java
// 재계산: O(1) 공간, O(2^n) 시간
int fibNoMemo(int n) {
    if (n <= 1) return n;
    return fibNoMemo(n-1) + fibNoMemo(n-2);
}

// 메모이제이션: O(n) 공간, O(n) 시간
int fibWithMemo(int n, int[] cache) {
    if (n <= 1) return n;
    if (cache[n] != -1) return cache[n];
    cache[n] = fibWithMemo(n-1, cache) + fibWithMemo(n-2, cache);
    return cache[n];
}
```

### 예시 3: 비트 벡터

```java
// 배열로 방문 체크: O(n) 공간
boolean[] visited = new boolean[n];

// 비트 벡터로 방문 체크: O(n/8) 공간 (8배 절약)
// n이 작을 때 (n <= 64) long 1개로 가능
long visited = 0L;
visited |= (1L << i);  // i번 방문
boolean isVisited = (visited & (1L << i)) != 0;
```

## 공간 복잡도 계산 예시

### 그래프 표현

```java
// 인접 행렬: O(V²) 공간
int[][] adjMatrix = new int[V][V];

// 인접 리스트: O(V + E) 공간
List<List<Integer>> adjList = new ArrayList<>();
for (int i = 0; i < V; i++) {
    adjList.add(new ArrayList<>());
}

// 희소 그래프 (E << V²): 인접 리스트가 유리
// 밀집 그래프 (E ≈ V²): 인접 행렬도 고려
```

### 동적 프로그래밍 최적화

반대로 이후 계산에서 더 이상 참조하지 않는 결과를 버리면 공간을 줄일 수 있다. 아래 LCS 예제는 전체 표를 저장하는 구현과 이전 행·현재 행만 유지하는 구현을 비교한다.

```java
// LCS (Longest Common Subsequence)
// 기본: O(mn) 공간
int[][] dp = new int[m + 1][n + 1];
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (s1.charAt(i-1) == s2.charAt(j-1)) {
            dp[i][j] = dp[i-1][j-1] + 1;
        } else {
            dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);
        }
    }
}

// 공간 최적화: O(n) 공간
// 현재 행은 이전 행에만 의존
int[] prev = new int[n + 1];
int[] curr = new int[n + 1];
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (s1.charAt(i-1) == s2.charAt(j-1)) {
            curr[j] = prev[j-1] + 1;
        } else {
            curr[j] = Math.max(prev[j], curr[j-1]);
        }
    }
    int[] temp = prev;
    prev = curr;
    curr = temp;
}
```

## 자료구조별 공간 복잡도

- 자료구조: 배열:
  - 공간 복잡도: O(n)
  - 비고: 연속 메모리
- 자료구조: 연결 리스트:
  - 공간 복잡도: O(n)
  - 비고: 노드당 포인터 오버헤드
- 자료구조: 해시 테이블:
  - 공간 복잡도: O(n)
  - 비고: 부하율에 따라 변동
- 자료구조: 이진 트리:
  - 공간 복잡도: O(n)
  - 비고: 노드당 2개 포인터
- 자료구조: 힙 (배열):
  - 공간 복잡도: O(n)
  - 비고: 오버헤드 적음
- 자료구조: 그래프 (인접 리스트):
  - 공간 복잡도: O(V + E)
  - 비고: 희소 그래프에 적합
- 자료구조: 그래프 (인접 행렬):
  - 공간 복잡도: O(V²)
  - 비고: 밀집 그래프에 적합

## 알고리즘별 공간 복잡도

- 알고리즘: 버블/선택/삽입 정렬:
  - Auxiliary Space: O(1)
  - 비고: In-place
- 알고리즘: 힙 정렬:
  - Auxiliary Space: O(1)
  - 비고: In-place
- 알고리즘: 퀵 정렬:
  - Auxiliary Space: O(log n)
  - 비고: 재귀 스택
- 알고리즘: 병합 정렬:
  - Auxiliary Space: O(n)
  - 비고: 임시 배열
- 알고리즘: BFS:
  - Auxiliary Space: O(V)
  - 비고: 큐
- 알고리즘: DFS (재귀):
  - Auxiliary Space: O(V)
  - 비고: 재귀 스택
- 알고리즘: DFS (반복):
  - Auxiliary Space: O(V)
  - 비고: 명시적 스택
- 알고리즘: 다익스트라:
  - Auxiliary Space: O(V)
  - 비고: 우선순위 큐
