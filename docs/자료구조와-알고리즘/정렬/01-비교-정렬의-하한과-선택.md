# 비교 정렬의 하한과 선택

비교 기반 정렬은 원소를 비교한 결과로 상대적인 순서를 결정한다. 가능한 모든 입력 순서를 구분하려면 충분한 비교가 필요하므로, 비교 횟수에는 Ω(n log n)의 하한이 생긴다. 이 하한을 결정 트리로 살펴본 뒤, 입력 조건이 달라지면 어떤 정렬을 선택할 수 있는지 연결해 보자.

## 정렬 알고리즘

### 정렬 알고리즘 비교

- 알고리즘: 버블 정렬:
  - 평균: O(n²)
  - 최악: O(n²)
  - 공간: O(1)
  - 안정성: 안정
- 알고리즘: 선택 정렬:
  - 평균: O(n²)
  - 최악: O(n²)
  - 공간: O(1)
  - 안정성: 불안정
- 알고리즘: 삽입 정렬:
  - 평균: O(n²)
  - 최악: O(n²)
  - 공간: O(1)
  - 안정성: 안정
- 알고리즘: 병합 정렬:
  - 평균: O(n log n)
  - 최악: O(n log n)
  - 공간: O(n)
  - 안정성: 안정
- 알고리즘: 퀵 정렬:
  - 평균: O(n log n)
  - 최악: O(n²)
  - 공간: O(log n)
  - 안정성: 불안정
- 알고리즘: 힙 정렬:
  - 평균: O(n log n)
  - 최악: O(n log n)
  - 공간: O(1)
  - 안정성: 불안정
- 알고리즘: 계수 정렬:
  - 평균: O(n + k)
  - 최악: O(n + k)
  - 공간: O(k)
  - 안정성: 안정
- 알고리즘: 기수 정렬:
  - 평균: O(d(n + k))
  - 최악: O(d(n + k))
  - 공간: O(n + k)
  - 안정성: 안정
- 알고리즘: 팀 정렬:
  - 평균: O(n log n)
  - 최악: O(n log n)
  - 공간: O(n)
  - 안정성: 안정

- 안정 정렬(Stable Sort): 동일한 값의 원소들이 정렬 후에도 원래 순서를 유지

## Decision Tree Model

비교 결과에 따라 다음 비교가 달라지는 흐름을 결정 트리(Decision Tree)로 나타낼 수 있다. 예를 들어 `a[1] < a[2]`의 결과가 참인지 거짓인지에 따라 `a[2] < a[3]` 또는 `a[1] < a[3]` 같은 다음 질문으로 내려간다.

- 결정 트리의 특성:
- 내부 노드: 두 원소 간의 비교 (예: `a[i] < a[j]?`)
- 리프 노드: 순열의 결과 (정렬된 순서)
- 경로: 루트에서 리프까지의 비교 시퀀스
- 트리 높이: 최악의 경우 비교 횟수

## 리프 노드의 개수

서로 다른 n개 원소의 순서는 n!가지다. 각 순서에 대해 올바른 결과를 결정해야 하므로, 결정 트리는 최소 n!개의 리프를 가져야 한다. 따라서 비교 횟수의 하한을 구하는 문제는 이만큼의 리프를 가진 이진 트리의 높이를 구하는 문제로 바뀐다.

## 트리 높이의 하한

- 정리: 높이가 h인 이진 트리는 최대 2^h 개의 리프를 가짐.

- 증명:
- 리프 개수 ≤ 2^h
- n! ≤ 2^h (결정 트리의 조건)
- h ≥ log₂(n!)

- log₂(n!)의 근사:

- 스털링 근사(Stirling's Approximation)를 사용:
- n! ≈ √(2πn) × (n/e)^n
- log₂(n!) = log₂(√(2πn)) + n × log₂(n/e)
- = Θ(n log n)

- 따라서: h = Ω(n log n)

## Information-Theoretic Lower Bound

정보량으로도 같은 결론에 도달한다. n!가지 중 올바른 순서 하나를 구분하려면 log₂(n!)비트가 필요하지만, 참·거짓으로 답하는 비교 한 번은 최대 1비트만 알려 준다. 따라서 필요한 비교 횟수는 최소 log₂(n!), 즉 Ω(n log n)이다.

## 정확한 상수 계산

- log₂(n!) = Σ(i=1 to n) log₂(i)
- ≥ Σ(i=n/2 to n) log₂(i)
- ≥ (n/2) × log₂(n/2)
- = (n/2) × (log₂(n) - 1)
- = (n log₂(n))/2 - n/2
- = Ω(n log n)

- 더 정밀한 하한:
- 최악의 경우: 약 n log₂(n) - 1.44n 번의 비교
- 평균의 경우도 동일한 Ω(n log n)

## 하한 증명이 적용되지 않는 경우

### 특수한 입력 분포

이 하한은 가능한 입력 전체를 구분해야 한다는 전제에서 나온다. 특정한 입력에서는 더 적은 비교로 끝날 수 있다. 아래 예제는 거의 정렬된 배열에 삽입 정렬을 적용하고 실제 비교 횟수를 센다.

```python
# 거의 정렬된 배열 - Insertion Sort가 O(n)
def insertion_sort(arr):
    comparisons = 0
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            comparisons += 1
            arr[j + 1] = arr[j]
            j -= 1
        comparisons += 1  # 마지막 비교
        arr[j + 1] = key
    return comparisons

# 거의 정렬된 배열
nearly_sorted = list(range(1000))
nearly_sorted[0], nearly_sorted[1] = nearly_sorted[1], nearly_sorted[0]
print(f"거의 정렬된 배열: {insertion_sort(nearly_sorted.copy())} 비교")
```

### 제한된 값 범위

- 정수이고 값의 범위가 O(n)이면:
- Counting Sort: O(n)
- Radix Sort: O(d × n) where d는 자릿수
