# 교착 상태의 조건과 사례

교착 상태(Deadlock)는 둘 이상의 프로세스가 서로 상대방이 가진 자원을 기다리며 진행하지 못하는 상태다. Process A가 Resource 1을 보유한 채 Resource 2를 기다리고, Process B는 Resource 2를 보유한 채 Resource 1을 기다리는 경우가 이에 해당한다. Lock X와 Lock Y를 반대 순서로 얻는 스레드 사이에서도 같은 대기 관계가 생길 수 있다.

## 교착 상태의 네 가지 필요조건

교착 상태가 발생하려면 다음 4가지 조건이 동시에 성립해야 한다. 하나라도 성립하지 않도록 만들면 교착 상태를 예방할 수 있다.

- 조건: 상호 배제:
  - 영문명: Mutual Exclusion
  - 설명: 자원은 한 번에 한 프로세스만 사용 가능
- 조건: 점유 대기:
  - 영문명: Hold and Wait
  - 설명: 자원을 점유한 채로 다른 자원을 대기
- 조건: 비선점:
  - 영문명: No Preemption
  - 설명: 다른 프로세스의 자원을 강제로 빼앗을 수 없음
- 조건: 순환 대기:
  - 영문명: Circular Wait
  - 설명: 프로세스들이 순환 형태로 서로의 자원을 대기

### 상호 배제 (Mutual Exclusion)

상호 배제는 한 번에 하나의 프로세스만 자원을 사용할 수 있다는 조건이다. P1이 Resource R을 사용 중이면 P2는 기다려야 한다. 프린터, 뮤텍스, 파일 쓰기 락처럼 자원을 비공유 모드로 사용하는 경우를 생각할 수 있다.

### 점유 대기 (Hold and Wait)

- 자원을 보유한 상태에서 다른 자원을 대기
- 이미 가진 자원을 놓지 않음

- P1: R1 보유 + R2 대기
- P1은 R1을 놓지 않고 R2를 기다림

```java
// 데드락 가능한 코드
synchronized(lockA) {     // lockA 점유
    // 다른 작업 수행
    synchronized(lockB) { // lockB 대기 (lockA 점유한 채로)
        // ...
    }
}
```

- 프로세스가 자원을 점유한 상태에서 추가 자원을 요청
- 점유한 자원을 놓지 않고 계속 보유

### 비선점 (No Preemption)

비선점은 이미 할당한 자원을 강제로 빼앗을 수 없다는 조건이다. P2가 R1을 필요로 해도 P1이 스스로 해제하기 전에는 가져갈 수 없으므로 기다린다.

### 순환 대기 (Circular Wait)

- 프로세스들이 순환 형태로 서로의 자원을 대기

- P1 → R2 대기 (P2가 보유)
- P2 → R3 대기 (P3가 보유)
- P3 → R1 대기 (P1이 보유)
- 순환 형성

- P0 → R1 → P1 → R2 → P2 → R0 → P0
- 순환
- P0이 R1을 기다림 (P1이 점유)
- P1이 R2를 기다림 (P2가 점유)
- P2가 R0을 기다림 (P0이 점유)

- 프로세스 집합 {P0, P1, ..., Pn}에서
- P0은 P1이 점유한 자원을 대기
- P1은 P2가 점유한 자원을 대기
- ...
- Pn은 P0이 점유한 자원을 대기

## 교착 상태 예시

### 예시 1: 두 프로세스의 교착 상태

- 시간순서:
- t1: P1이 R1 획득
- t2: P2가 R2 획득
- t3: P1이 R2 요청 → 대기 (P2가 보유)
- t4: P2가 R1 요청 → 대기 (P1이 보유)
- → 교착 상태!

- P1, P2
- [R1 보유], [R2 보유]
- R2 대기, ← →, R1 대기
- 교착 상태

### 예시 2: 코드로 보는 교착 상태

```java
// Thread 1
synchronized(lockA) {
    // lockA 획득
    Thread.sleep(100);
    synchronized(lockB) {  // lockB 대기
        // 작업
    }
}

// Thread 2
synchronized(lockB) {
    // lockB 획득
    Thread.sleep(100);
    synchronized(lockA) {  // lockA 대기 → 데드락!
        // 작업
    }
}
```

## 자원 할당 그래프 (Resource Allocation Graph)

- 교착 상태 상태를 시각화하는 방법임.

```text
P : 프로세스 (P)
R : 자원 (R)
→ : 요청 (P → R)
← : 할당 (R → P)

데드락 상태:
    ┌─────────────┐
    ↓             │
  [P1] ← [R1]     │
    │             │
    │             │
    ↓             │
  [R2] → [P2] ────┘
```

- 사이클 존재 = 교착 상태 가능성
- 자원당 인스턴스 1개: 사이클 = 교착 상태
- 자원당 인스턴스 여러 개: 사이클이 있어도 교착 상태 아닐 수 있음

- 교착 상태를 시각적으로 표현하고 탐지하는 도구임.

### 그래프 구성 요소

- ○ : 프로세스 (Process)
- : 자원 유형 (Resource Type)
- : 자원 인스턴스 (Resource Instance)
- P → R : 요청 간선 (Request Edge) - P가 R을 요청
- R → P : 할당 간선 (Assignment Edge) - R이 P에 할당됨

### 교착 상태 상태 예시

- 요청
- P1, → R1
- 할당, 할당
- R2 ←, P2
- 요청
- P1: R2 점유, R1 요청
- P2: R1 점유, R2 요청
- → 순환(사이클) 발생 → 교착 상태

### 사이클과 교착 상태 관계

- 상황: 사이클 없음:
  - 교착 상태 여부: 교착 상태 없음 (반드시)
- 상황: 사이클 있음 + 자원당 인스턴스 1개:
  - 교착 상태 여부: 교착 상태 (반드시)
- 상황: 사이클 있음 + 자원당 인스턴스 여러 개:
  - 교착 상태 여부: 교착 상태 가능성 (반드시는 아님)

### 인스턴스가 여러 개인 경우

자원 유형 R1과 R2에 각각 인스턴스가 2개 있다고 하자. R1의 두 인스턴스를 P1과 P2가 사용하면서 모두 R2를 요청하더라도, R2가 다른 프로세스에 할당되어 되돌아오는 간선이 없다면 사이클은 없다. 가용한 R2 인스턴스를 할당하면 진행할 수 있다.

인스턴스가 여러 개인 경우에는 사이클이 있더라도 교착 상태라고 확정할 수 없다. 현재 가용량뿐 아니라 다른 프로세스가 완료하면서 돌려줄 자원까지 확인해야 한다.

## 실무에서의 교착 상태

### 데이터베이스 교착 상태

```sql
-- Transaction 1
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
-- T1: id=1 락
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
-- T1: id=2 대기 (T2가 보유)

-- Transaction 2
BEGIN;
UPDATE accounts SET balance = balance - 50 WHERE id = 2;
-- T2: id=2 락
UPDATE accounts SET balance = balance + 50 WHERE id = 1;
-- T2: id=1 대기 (T1이 보유)
-- 데드락!
```

- 해결: 항상 같은 순서로 락 획득

```sql
-- 항상 id 오름차순으로 락
-- Transaction 1 & 2 모두
BEGIN;
UPDATE accounts SET balance = ... WHERE id = 1;  -- 먼저
UPDATE accounts SET balance = ... WHERE id = 2;  -- 나중
COMMIT;
```

### 멀티스레드 프로그래밍

- Lock Ordering:

```java
// 모든 스레드가 같은 순서로 락 획득
Object lock1 = new Object();
Object lock2 = new Object();

void method() {
    synchronized(lock1) {  // 항상 lock1 먼저
        synchronized(lock2) {
            // 작업
        }
    }
}
```

- Lock Timeout:

```java
if (lock.tryLock(1, TimeUnit.SECONDS)) {
    try {
        // 작업
    } finally {
        lock.unlock();
    }
} else {
    // 타임아웃 - 데드락 회피
}
```

## 라이브락과 기아

- 상태: 교착 상태 (Deadlock):
  - 설명: 서로 상대방의 자원을 기다리며 무한 대기
  - 특징: 프로세스가 정지
- 상태: 라이브락 (Livelock):
  - 설명: 서로 양보하며 무한 반복
  - 특징: 프로세스가 동작하지만 진행 안 됨
- 상태: 기아 (Starvation):
  - 설명: 자원을 영원히 할당받지 못함
  - 특징: 특정 프로세스만 불이익

### Livelock

- 프로세스가 상태를 계속 변경하지만 진전이 없음
- 교착 상태과 달리 "활동"은 하지만 유용한 작업 없음

- 복도에서 두 사람이 서로 비키려다 같은 방향으로 계속 움직임
- A: 왼쪽 → 오른쪽 → 왼쪽 → ...
- B: 오른쪽 → 왼쪽 → 오른쪽 → ...

### Starvation (기아)

- 특정 프로세스가 자원을 영원히 얻지 못함
- 우선순위가 낮은 프로세스가 계속 밀림

- P1(높은 우선순위) → 자원 획득
- P2(높은 우선순위) → 자원 획득
- P3(낮은 우선순위) → 무한 대기...

### 라이브락 예시

- 복도에서 두 사람이 마주침
- A: 오른쪽으로 비킴 ←→ B: 왼쪽으로 비킴 (여전히 마주침)
- A: 왼쪽으로 비킴, ←→ B: 오른쪽으로 비킴 (여전히 마주침)
- ... 무한 반복 ...

```java
// 라이브락 예시 코드
while (resourceInUse) {
    // 양보
    Thread.yield();
    // 다시 시도 → 상대방도 같은 행동 → 무한 반복
}
```

### 기아 예시

- 우선순위 스케줄링에서:
- 높은 우선순위 프로세스들이 계속 도착
- 낮은 우선순위 프로세스는 영원히 CPU 할당 못 받음
- 기아 상태

## 교착 상태 예제 코드

### Java에서의 교착 상태

```java
public class DeadlockExample {
    private final Object lockA = new Object();
    private final Object lockB = new Object();

    public void method1() {
        synchronized (lockA) {
            System.out.println("Thread 1: Holding lockA");
            try { Thread.sleep(100); } catch (InterruptedException e) {}

            System.out.println("Thread 1: Waiting for lockB");
            synchronized (lockB) {
                System.out.println("Thread 1: Holding lockA & lockB");
            }
        }
    }

    public void method2() {
        synchronized (lockB) {  // 순서가 다름!
            System.out.println("Thread 2: Holding lockB");
            try { Thread.sleep(100); } catch (InterruptedException e) {}

            System.out.println("Thread 2: Waiting for lockA");
            synchronized (lockA) {
                System.out.println("Thread 2: Holding lockB & lockA");
            }
        }
    }
}
```

### 실행 흐름

- Time, Thread 1, Thread 2
- t0, lockA 획득, lockB 획득
- t1, lockB 대기, lockA 대기
- t2, ...대기..., ...대기...
- 교착 상태 발생

### C/pthreads에서의 교착 상태

```c
pthread_mutex_t mutex1 = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t mutex2 = PTHREAD_MUTEX_INITIALIZER;

void* thread1_func(void* arg) {
    pthread_mutex_lock(&mutex1);
    sleep(1);  // 데드락 발생 확률 높임
    pthread_mutex_lock(&mutex2);

    // 임계 구역

    pthread_mutex_unlock(&mutex2);
    pthread_mutex_unlock(&mutex1);
    return NULL;
}

void* thread2_func(void* arg) {
    pthread_mutex_lock(&mutex2);  // 순서가 다름!
    sleep(1);
    pthread_mutex_lock(&mutex1);

    // 임계 구역

    pthread_mutex_unlock(&mutex1);
    pthread_mutex_unlock(&mutex2);
    return NULL;
}
```

## 실제 교착 상태 사례

### 데이터베이스 트랜잭션

```sql
-- Transaction A
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;  -- Row 1 락
UPDATE accounts SET balance = balance + 100 WHERE id = 2;  -- Row 2 대기

-- Transaction B (동시 실행)
BEGIN;
UPDATE accounts SET balance = balance - 50 WHERE id = 2;   -- Row 2 락
UPDATE accounts SET balance = balance + 50 WHERE id = 1;   -- Row 1 대기

-- 데드락 발생!
```

### 파일 시스템

- Process A: file1.txt 락 → file2.txt 요청
- Process B: file2.txt 락 → file1.txt 요청

### 분산 시스템

- Node A: Resource X 락 → Node B의 Resource Y 요청
- Node B: Resource Y 락 → Node A의 Resource X 요청
