# 인터넷 작동 원리

인터넷에서 데이터가 목적지에 도착하려면 전송 자원을 나누고, 주소를 구분하고, 다음 경로를 선택해야 한다. 패킷 스위칭부터 IP 주소와 라우팅을 살펴본 뒤, 여러 ISP가 연결되는 구조로 범위를 넓힌다.

## 패킷 스위칭과 회선 스위칭

### 회선 스위칭 (Circuit Switching)

회선 스위칭은 통신을 시작하기 전에 송신자와 수신자 사이에 전용 경로를 설정한다. 발신자에서 교환기를 거쳐 수신자까지 이어지는 회선을 통신하는 동안 독점해서 사용한다.

- 특징:
- 통신 전 연결 설정 단계(Call Setup) 필요
- 연결 동안 대역폭이 보장됨
- 자원의 비효율적 사용 (통화 중 침묵 시간에도 회선 점유)
- 대표적 예: 전통적인 전화 네트워크 (PSTN)

- 회선 스위칭의 대역폭 계산:
- 총 대역폭: 1 Mbps
- 회선당 대역폭: 100 Kbps
- 동시 연결 가능 수: 1,000,000 / 100,000 = 10개

### 패킷 스위칭 (Packet Switching)

패킷 스위칭은 데이터를 작은 패킷으로 나누어 전송하는 방식으로, 현대 인터넷의 기반이다. 예를 들어 `ABCDEFGHIJ`를 `ABC`, `DEF`, `GHIJ`로 나누고 각각에 헤더를 붙여 보낼 수 있다.

이 예제에서 첫 패킷은 라우터 1과 3, 두 번째는 라우터 2와 4, 세 번째는 라우터 1과 4를 거쳐 목적지에 도착한다. 수신 측은 나뉜 데이터를 다시 조립해 원본을 얻는다.

- IPv4 헤더는 다음 필드가 순서대로 배치되는 구조임. [RFC 791](https://www.rfc-editor.org/rfc/rfc791.html) 참고.
  - Version 4비트와 IHL 4비트: 버전과 헤더 길이를 나타냄. IHL은 32비트 워드 단위이며 5보다 크면 옵션이 포함됨.
  - Type of Service 8비트: 서비스 구분 영역이며 DSCP 6비트와 ECN 2비트로 구분하여 사용함.
  - Total Length 16비트: 헤더를 포함한 패킷 전체 길이임.
  - Identification 16비트, Flags 3비트, Fragment Offset 13비트: 단편의 식별과 재조립에 사용함.
  - Time to Live 8비트와 Protocol 8비트: 패킷의 수명과 상위 프로토콜을 나타냄.
  - Header Checksum 16비트: IPv4 헤더의 오류를 검출함.
  - Source Address와 Destination Address: 각각 32비트의 출발지와 목적지 주소임.
  - Options와 Padding: 선택 기능과 32비트 경계 정렬에 사용함.
- 옵션을 제외한 IPv4 헤더는 20바이트이며, 옵션을 포함하면 최대 60바이트임. 헤더 뒤에 Data가 이어짐.

### 패킷 스위칭 방식 비교

- 구분: 연결 설정:
  - 데이터그램 방식: 불필요
  - 가상 회선 방식: 필요
- 구분: 패킷 경로:
  - 데이터그램 방식: 독립적 (다를 수 있음)
  - 가상 회선 방식: 동일 경로
- 구분: 순서 보장:
  - 데이터그램 방식: X (재정렬 필요)
  - 가상 회선 방식: O
- 구분: 예시:
  - 데이터그램 방식: IP, UDP
  - 가상 회선 방식: ATM, MPLS, TCP

### Store-and-Forward vs Cut-Through

Store-and-Forward는 패킷 전체를 받은 뒤 다음 홉으로 보낸다. 아래 코드는 전파 지연이나 큐 대기를 제외하고 패킷 크기, 링크 대역폭, 홉 수만으로 전송 지연을 계산한다.

```python
# Store-and-Forward 지연 시간 계산
def store_and_forward_delay(packet_size, link_bandwidth, num_hops):
    """
    패킷 전체를 수신한 후 다음 홉으로 전송

    Args:
        packet_size: 패킷 크기 (bits)
        link_bandwidth: 링크 대역폭 (bps)
        num_hops: 홉 수

    Returns:
        total_delay: 총 전송 지연 (seconds)
    """
    transmission_delay = packet_size / link_bandwidth
    total_delay = num_hops * transmission_delay
    return total_delay

# 예시: 1500 bytes 패킷, 100 Mbps 링크, 3홉
packet_size = 1500 * 8  # 12,000 bits
link_bandwidth = 100 * 10**6  # 100 Mbps
num_hops = 3

delay = store_and_forward_delay(packet_size, link_bandwidth, num_hops)
print(f"Store-and-Forward 지연: {delay * 1000:.3f} ms")  # 0.360 ms
```

### 회선 스위칭 vs 패킷 스위칭 비교표

- 특성: 연결 설정:
  - 회선 스위칭: 필요 (Call Setup)
  - 패킷 스위칭: 불필요
- 특성: 대역폭:
  - 회선 스위칭: 고정 할당
  - 패킷 스위칭: 동적 공유
- 특성: 지연 시간:
  - 회선 스위칭: 일정
  - 패킷 스위칭: 가변적 (큐잉 지연)
- 특성: 자원 효율성:
  - 회선 스위칭: 낮음
  - 패킷 스위칭: 높음
- 특성: 신뢰성:
  - 회선 스위칭: 경로 장애 시 통신 불가
  - 패킷 스위칭: 대체 경로 사용 가능
- 특성: 적합한 서비스:
  - 회선 스위칭: 음성 통화
  - 패킷 스위칭: 데이터 통신

## IP 주소 체계 (IPv4, IPv6)

### IPv4 (RFC 791)

- 주소 구조: 32비트, 약 43억 개의 주소 (2^32 = 4,294,967,296)

- A:
  - 네트워크 범위: 0.0.0.0 ~ 127.255.255.255
  - 용도: 대규모 네트워크
- B:
  - 네트워크 범위: 128.0.0.0 ~ 191.255.255.255
  - 용도: 중규모 네트워크
- C:
  - 네트워크 범위: 192.0.0.0 ~ 223.255.255.255
  - 용도: 소규모 네트워크
- D:
  - 네트워크 범위: 224.0.0.0 ~ 239.255.255.255
  - 용도: 멀티캐스트
- E:
  - 네트워크 범위: 240.0.0.0 ~ 255.255.255.255
  - 용도: 예약됨
- IP 주소: 192.168.1.100
- 이진수:  11000000.10101000.00000001.01100100
- 클래스 기반 주소 체계 (Legacy):

- CIDR (Classless Inter-Domain Routing) - RFC 4632:

```python
# CIDR 표기법과 서브넷 계산
def calculate_subnet_info(cidr_notation):
    """
    CIDR 표기법으로 서브넷 정보 계산

    Args:
        cidr_notation: "192.168.1.0/24" 형태의 CIDR 표기

    Returns:
        dict: 네트워크 정보
    """
    import ipaddress

    network = ipaddress.ip_network(cidr_notation, strict=False)

    return {
        "network_address": str(network.network_address),
        "broadcast_address": str(network.broadcast_address),
        "netmask": str(network.netmask),
        "num_hosts": network.num_addresses - 2,  # 네트워크, 브로드캐스트 제외
        "host_range": f"{network.network_address + 1} ~ {network.broadcast_address - 1}",
        "prefix_length": network.prefixlen
    }

# 사용 예시
info = calculate_subnet_info("192.168.1.0/24")
print(f"네트워크 주소: {info['network_address']}")
print(f"브로드캐스트: {info['broadcast_address']}")
print(f"서브넷 마스크: {info['netmask']}")
print(f"사용 가능 호스트 수: {info['num_hosts']}")
```

- 사설 IP 주소 (RFC 1918):
- 10.0.0.0/8, (10.0.0.0 ~ 10.255.255.255), - 16,777,216 주소
- 172.16.0.0/12, (172.16.0.0 ~ 172.31.255.255), - 1,048,576 주소
- 192.168.0.0/16, (192.168.0.0 ~ 192.168.255.255), - 65,536 주소

### IPv6 (RFC 8200)

- 주소 구조: 128비트, 약 3.4 x 10^38 개의 주소

- IPv6 주소 형식:
- 2001:0db8:85a3:0000:0000:8a2e:0370:7334
- 축약 규칙:
- 선행 0 생략: 0db8 → db8
- 연속된 0 그룹은 ::로 한 번만 생략 가능
- 축약 후: 2001:db8:85a3::8a2e:370:7334

- IPv6 주소 유형:
- 유니캐스트:
  - 설명: 단일 인터페이스 식별
- 글로벌:
  - 설명: 2000::/3 (인터넷에서 라우팅 가능)
- 링크 로컬:
  - 설명: fe80::/10 (로컬 링크 내에서만 유효)
- 유니크 로컬:
  - 설명: fc00::/7 (사설 네트워크, IPv4의 RFC 1918 대응)
- 멀티캐스트:
  - 설명: ff00::/8 (그룹 통신)
- 애니캐스트:
  - 설명: 유니캐스트와 동일 형식 (가장 가까운 노드로 전달)

- IPv6 기본 헤더는 40바이트이며 다음 순서로 구성됨. [RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html) 참고.
  - Version 4비트, Traffic Class 8비트, Flow Label 20비트가 버전과 트래픽 및 흐름을 식별함.
  - Payload Length 16비트, Next Header 8비트, Hop Limit 8비트가 페이로드 길이, 다음 헤더 종류, 전달 가능한 홉 수를 나타냄.
  - Source Address와 Destination Address는 각각 128비트임.
- 확장 헤더는 고정 40바이트의 기본 헤더 뒤에 연결됨.

### IPv4 vs IPv6 비교

- 특성: 주소 크기:
  - IPv4: 32비트
  - IPv6: 128비트
- 특성: 주소 표기:
  - IPv4: 점-십진수 (192.168.1.1)
  - IPv6: 콜론-16진수 (2001:db8::1)
- 특성: 헤더 크기:
  - IPv4: 20-60 bytes (가변)
  - IPv6: 40 bytes (고정)
- 특성: 체크섬:
  - IPv4: 있음
  - IPv6: 없음 (상위 계층에 위임)
- 특성: NAT 필요성:
  - IPv4: 높음
  - IPv6: 낮음
- 특성: IPSec:
  - IPv4: 선택적
  - IPv6: 필수 지원
- 특성: 주소 설정:
  - IPv4: DHCP 또는 수동
  - IPv6: SLAAC 또는 DHCPv6

## 라우팅 프로토콜 (BGP, OSPF)

### 라우팅 프로토콜 분류

- 라우팅 프로토콜
- IGP (Interior Gateway Protocol) - AS 내부
- Distance Vector
- RIP (Routing Information Protocol)
- EIGRP (Enhanced IGRP)
- Link State
- OSPF (Open Shortest Path First)
- IS-IS (Intermediate System to IS)
- EGP (Exterior Gateway Protocol) - AS 간

### OSPF (Open Shortest Path First)

- RFC 2328 (OSPFv2), RFC 5340 (OSPFv3)

- OSPF는 링크 상태 라우팅 프로토콜로, 각 라우터가 네트워크 토폴로지 전체의 정보를 유지하고 Dijkstra 알고리즘을 사용하여 최단 경로를 계산함.

- OSPF 영역 구조:
- Area 0 (Backbone)
- ABR, ABR
- Area 1, Area 2
- R, R
- ABR: Area Border Router (영역 경계 라우터)

- OSPF 패킷 유형:
- Hello:
  - 설명: 이웃 발견 및 관계 유지 (기본 10초 간격)
- DBD:
  - 설명: Database Description - LSA 헤더 요약 교환
- LSR:
  - 설명: Link State Request - 특정 LSA 요청
- LSU:
  - 설명: Link State Update - LSA 전달
- LSAck:
  - 설명: Link State Acknowledgment - LSA 수신 확인

- OSPF 메트릭 계산:

```python
# OSPF 비용(Cost) 계산
def calculate_ospf_cost(bandwidth_bps, reference_bandwidth=100_000_000):
    """
    OSPF 인터페이스 비용 계산

    Cost = Reference Bandwidth / Interface Bandwidth
    기본 Reference Bandwidth: 100 Mbps

    Args:
        bandwidth_bps: 인터페이스 대역폭 (bps)
        reference_bandwidth: 참조 대역폭 (기본 100 Mbps)

    Returns:
        cost: OSPF 비용 (최소 1)
    """
    cost = reference_bandwidth / bandwidth_bps
    return max(1, int(cost))

# 예시
interfaces = {
    "FastEthernet (100 Mbps)": 100_000_000,
    "GigabitEthernet (1 Gbps)": 1_000_000_000,
    "10GigabitEthernet (10 Gbps)": 10_000_000_000,
}

for name, bandwidth in interfaces.items():
    cost = calculate_ospf_cost(bandwidth)
    print(f"{name}: Cost = {cost}")

# 출력:
# FastEthernet (100 Mbps): Cost = 1
# GigabitEthernet (1 Gbps): Cost = 1  # 기본 참조 대역폭으로는 구분 불가
# 10GigabitEthernet (10 Gbps): Cost = 1

# 고속 링크 구분을 위해 참조 대역폭 조정 필요
for name, bandwidth in interfaces.items():
    cost = calculate_ospf_cost(bandwidth, reference_bandwidth=10_000_000_000)
    print(f"{name}: Cost = {cost} (ref: 10 Gbps)")

# 출력:
# FastEthernet (100 Mbps): Cost = 100
# GigabitEthernet (1 Gbps): Cost = 10
# 10GigabitEthernet (10 Gbps): Cost = 1
```

- Dijkstra 알고리즘 (SPF):

```python
import heapq
from collections import defaultdict

def dijkstra_spf(graph, source):
    """
    Dijkstra 알고리즘을 사용한 최단 경로 계산
    OSPF가 내부적으로 사용하는 알고리즘

    Args:
        graph: 인접 리스트 형태의 그래프 {node: [(neighbor, cost), ...]}
        source: 출발 노드

    Returns:
        distances: 각 노드까지의 최단 거리
        previous: 최단 경로 역추적용 이전 노드
    """
    distances = defaultdict(lambda: float('inf'))
    distances[source] = 0
    previous = {}

    # 우선순위 큐: (거리, 노드)
    pq = [(0, source)]
    visited = set()

    while pq:
        current_dist, current = heapq.heappop(pq)

        if current in visited:
            continue
        visited.add(current)

        for neighbor, cost in graph[current]:
            distance = current_dist + cost

            if distance < distances[neighbor]:
                distances[neighbor] = distance
                previous[neighbor] = current
                heapq.heappush(pq, (distance, neighbor))

    return dict(distances), previous

# OSPF 네트워크 토폴로지 예시
ospf_network = {
    'R1': [('R2', 10), ('R3', 5)],
    'R2': [('R1', 10), ('R3', 2), ('R4', 1)],
    'R3': [('R1', 5), ('R2', 2), ('R4', 9)],
    'R4': [('R2', 1), ('R3', 9)]
}

distances, previous = dijkstra_spf(ospf_network, 'R1')
print(f"R1에서 각 라우터까지의 최단 비용: {distances}")
# {'R1': 0, 'R3': 5, 'R2': 7, 'R4': 8}
```

### BGP (Border Gateway Protocol)

- RFC 4271 (BGP-4)

- BGP는 자율 시스템(AS) 간 라우팅을 담당하는 Path Vector 프로토콜임. 인터넷의 핵심 라우팅 프로토콜임.

- BGP 특징:
- TCP 포트 179 사용 (신뢰성 있는 전송)
- 정책 기반 라우팅 (Policy-based Routing)
- 느린 수렴 속도 (안정성 우선)
- AS-PATH를 통한 루프 방지

- BGP 메시지 유형:
- OPEN:
  - 설명: BGP 세션 시작, AS 번호/Hold Time 등 협상

### IXP (Internet Exchange Point)

- IXP는 여러 ISP들이 트래픽을 직접 교환할 수 있는 물리적 인프라임.

- IXP
- ISP A, →, L2 Switch, ←, ISP B
- (고속 스위칭)
- ISP C, →, ←, ISP D
- ISP E, →, ←, CDN
- Route Server
- (BGP 세션 관리)

- IXP의 장점:
- 지연 감소: 트래픽이 상위 ISP를 거치지 않고 직접 교환
- 비용 절감: Transit 비용 대신 저렴한 Peering 비용
- 대역폭 증가: 병목 현상 감소
- 지역 트래픽 최적화: 로컬 트래픽이 지역 내에서 처리
