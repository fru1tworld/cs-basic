# 전송 프로토콜 선택

TCP와 UDP는 OSI 7계층 중 전송 계층에서 애플리케이션 간 데이터 전송을 담당한다. TCP는 RFC 793, UDP는 RFC 768에 정의되어 있다. 둘을 선택할 때는 전달 순서와 손실 복구가 필요한지, 지연과 연결 관리 비용을 얼마나 허용할 수 있는지 살펴봐야 한다.

## 전송 계층의 역할

전송 계층은 포트 번호로 통신 대상을 구분해 프로세스 간 통신을 지원한다. TCP는 데이터를 세그먼트로 나누고 연결을 설정·해제하며, 오류 검출과 순서 제어, 재전송을 제공한다. 수신자가 처리할 수 있는 양은 흐름 제어로, 네트워크가 감당할 수 있는 양은 혼잡 제어로 조절한다.

## TCP vs UDP 비교

### 상세 비교표

- 구분: 연결 방식:
  - TCP: 연결 지향 (3-way Handshake)
  - UDP: 비연결
- 구분: 신뢰성:
  - TCP: 보장 (재전송, 순서 보장)
  - UDP: 보장 안함
- 구분: 헤더 크기:
  - TCP: 20-60 bytes
  - UDP: 8 bytes
- 구분: 속도:
  - TCP: 상대적으로 느림
  - UDP: 빠름
- 구분: 흐름 제어:
  - TCP: 있음 (Sliding Window)
  - UDP: 없음
- 구분: 혼잡 제어:
  - TCP: 있음 (AIMD, Slow Start 등)
  - UDP: 없음
- 구분: 순서 보장:
  - TCP: 보장
  - UDP: 보장 안함
- 구분: 오류 검출:
  - TCP: Checksum + 재전송
  - UDP: Checksum만
- 구분: 전송 단위:
  - TCP: 바이트 스트림
  - UDP: 데이터그램 (메시지)
- 구분: 브로드캐스트:
  - TCP: 지원 안함
  - UDP: 지원
- 구분: 멀티캐스트:
  - TCP: 지원 안함
  - UDP: 지원
- 구분: 적용 분야:
  - TCP: 웹, 이메일, 파일 전송
  - UDP: DNS, 스트리밍, 게임, VoIP

### 시각적 비교

- TCP 통신 과정:
- Client, Server
- Client → SYN → Server
- Server → SYN+ACK → Client
- Client → ACK , 연결 설정 → Server
- (3-way)
- DATA, >
- <, ACK, 데이터 전송
- DATA, >, (신뢰성 보장)
- <, ACK
- Client → FIN → Server
- Server → ACK, 연결 종료 → Client
- Server → FIN, (4-way) → Client
- Client → ACK → Server
- UDP 통신 과정:
- Client, Server
- DATA, >
- DATA, >, 바로 전송
- DATA, >, (연결 없음)

## UDP vs TCP 비교

- 특성: 연결:
  - TCP: 연결 지향
  - UDP: 비연결형
- 특성: 신뢰성:
  - TCP: 보장
  - UDP: 비보장
- 특성: 순서:
  - TCP: 보장
  - UDP: 비보장
- 특성: 속도:
  - TCP: 상대적 느림
  - UDP: 빠름
- 특성: 오버헤드:
  - TCP: 높음 (20+ bytes)
  - UDP: 낮음 (8 bytes)
- 특성: 흐름 제어:
  - TCP: 있음
  - UDP: 없음
- 특성: 혼잡 제어:
  - TCP: 있음
  - UDP: 없음
- 특성: 1:1 / 1:N:
  - TCP: 1:1
  - UDP: 1:1, 1:N, N:N

## 핵심 비교

### 전체 비교표

- 특성: 연결 방식:
  - TCP: 연결 지향 (3-Way Handshake)
  - UDP: 비연결형
- 특성: 신뢰성:
  - TCP: 보장 (ACK, 재전송)
  - UDP: 비보장
- 특성: 순서 보장:
  - TCP: 보장 (Sequence Number)
  - UDP: 비보장
- 특성: 흐름 제어:
  - TCP: 있음 (Sliding Window)
  - UDP: 없음
- 특성: 혼잡 제어:
  - TCP: 있음 (Slow Start 등)
  - UDP: 없음
- 특성: 속도:
  - TCP: 상대적 느림
  - UDP: 빠름
- 특성: 헤더 크기:
  - TCP: 20~60 bytes
  - UDP: 8 bytes
- 특성: 전송 단위:
  - TCP: Segment
  - UDP: Datagram
- 특성: 통신 방식:
  - TCP: 1:1
  - UDP: 1:1, 1:N, N:N
- 특성: 사용 예:
  - TCP: HTTP, HTTPS, FTP, SMTP
  - UDP: DNS, DHCP, 스트리밍, 게임

### 연결 설정 비교

#### TCP

- Client, Server
- Client → SYN → Server
- Server → SYN + ACK → Client
- Client → ACK → Server
- [연결 수립]
- Client → Data → Server
- Server → ACK → Client

#### UDP

- Client, Server
- Client → Data → Server
- Client → Data → Server
- Client → Data → Server

- 핵심 차이: TCP는 연결 설정에 1.5 RTT 필요, UDP는 즉시 전송

### 데이터 전송 비교

#### TCP - 신뢰성 있는 전송

- 송신: [1][2][3][4][5]
- 네트워크: [2] 손실
- 수신: [1][_][3][4][5]
- ACK: "2번 없음"
- 재전송: [2]
- 수신: [1][2][3][4][5] ← 순서대로 정렬

#### UDP - 최선 노력 전송

- 송신: [1][2][3][4][5]
- 네트워크: [2] 손실
- 수신: [1][3][4][5] ← 손실된 채로 전달

### 헤더 구조 비교

#### TCP 헤더 (20~60 bytes)

- Source Port, Destination Port, 4 bytes
- Sequence Number, 4 bytes
- Acknowledgment Number, 4 bytes
- Offset Reserved Flags, Window, 4 bytes
- Checksum, Urgent Pointer, 4 bytes
- Options (optional), 0-40 bytes

#### UDP 헤더 (8 bytes)

- Source Port, Destination Port, 4 bytes
- Length, Checksum, 4 bytes

- 오버헤드 차이: TCP는 UDP보다 최소 12바이트 더 큼

### 사용 시나리오

#### TCP가 적합한 경우

- 시나리오: 웹 브라우징 (HTTP/HTTPS):
  - 이유: 페이지가 완전히 로드되어야 함
- 시나리오: 이메일 (SMTP, IMAP):
  - 이유: 메시지 손실 불가
- 시나리오: 파일 전송 (FTP):
  - 이유: 파일 무결성 필수
- 시나리오: 원격 접속 (SSH):
  - 이유: 명령어 손실 시 문제
- 시나리오: 데이터베이스 연결:
  - 이유: 트랜잭션 무결성

- 웹 페이지 로딩:
- [HTML] → [CSS] → [JS] → [Images]
- 모든 리소스가 완전히 전달되어야 함

#### UDP가 적합한 경우

- 시나리오: 실시간 스트리밍:
  - 이유: 지연 > 손실
- 시나리오: 온라인 게임:
  - 이유: 빠른 응답 필요
- 시나리오: VoIP:
  - 이유: 실시간 통화
- 시나리오: DNS 조회:
  - 이유: 짧은 요청/응답
- 시나리오: IoT 센서 데이터:
  - 이유: 연속 데이터, 일부 손실 무관

- 실시간 스트리밍:
- Frame1 → Frame2 → [Frame3 손실] → Frame4 → Frame5
- 재전송 기다리면 영상 끊김
- → 다음 프레임으로 진행

### 성능 비교

#### 지연 시간 (Latency)

- TCP 첫 데이터 전송:
- [SYN] → [SYN+ACK] → [ACK] → [Data]
- 1 RTT, +, 데이터 전송
- UDP 첫 데이터 전송:
- [Data]
- 즉시 전송

#### 처리량 (Throughput)

- TCP: 혼잡 제어로 인해 동적 조절
- UDP: 애플리케이션이 결정, 제한 없음

#### 오버헤드

- 1000개의 100바이트 메시지 전송 시 헤더 오버헤드:
- TCP: 1000 × 20 = 20,000 bytes (최소)
- UDP: 1000 × 8 = 8,000 bytes

### 하이브리드 접근법

#### QUIC (HTTP/3)

- UDP 기반 + TCP의 신뢰성
- 빠른 연결 설정 (0-RTT)
- 멀티플렉싱
- 암호화 내장

- TCP+TLS:
- [SYN] → [SYN+ACK] → [ACK] → [TLS 핸드셰이크] → [Data]
- 1 RTT, + 1-2 RTT
- QUIC:
- [Initial+Crypto+Data]
- 0-1 RTT (재연결 시 0-RTT)

#### 애플리케이션 레벨 신뢰성

- UDP + 자체 ACK 구현:
- Client, Server
- Client → Data(seq=1) → Server
- Server → ACK(1) → Client
- Client → Data(seq=2) , (손실) → Server
- [Timeout]
- Client → Data(seq=2) , (재전송) → Server
- Server → ACK(2) → Client

## 선택 가이드

### 결정 트리

데이터 손실과 순서 복원을 전송 프로토콜에 맡기려면 TCP를 고려한다. 일부 손실을 허용할 수 있고 실시간성이 중요하다면 UDP를 검토하되, 애플리케이션에서 추가로 처리해야 할 기능까지 함께 판단한다.

### 체크리스트

- TCP 선택 조건:
- [ ] 모든 데이터가 정확히 도착해야 함
- [ ] 순서가 중요함
- [ ] 신뢰성이 최우선
- [ ] 연결 설정 오버헤드 감수 가능

- UDP 선택 조건:
- [ ] 실시간성이 중요함
- [ ] 약간의 손실 허용 가능
- [ ] 낮은 지연이 필수
- [ ] 브로드캐스트/멀티캐스트 필요
- [ ] 자체 신뢰성 메커니즘 구현 가능
