# 형식 언어

형식 언어(Formal Language)는 특정 알파벳, 즉 기호 집합으로 만든 문자열의 집합이다. 문자열이 언어에 속하는 조건을 수학적으로 정의하므로 프로그래밍 언어의 구문(Syntax)을 분석하는 기반이 된다. 컴파일러 설계뿐 아니라 자연어 처리와 패턴 매칭에도 쓰인다.

형식 언어 이론에서는 언어의 종류를 구분하고, 각각을 인식하는 데 어떤 계산 능력이 필요한지 살펴본다.

## 기본 정의

알파벳(Alphabet) Σ는 유한한 기호의 집합이다. `{0, 1}`, `{a, b, c}`, `{if, else, while, ...}`가 예다. 이 기호를 유한하게 나열하면 `"0110"`, `"abc"`, `"if while"` 같은 문자열(String)이 되며, 기호가 하나도 없는 빈 문자열은 ε(epsilon)로 쓴다.

Σ\*(Kleene Closure)는 ε를 포함해 Σ로 만들 수 있는 모든 문자열의 집합이다. 예를 들어 `{0,1}* = {ε, 0, 1, 00, 01, 10, 11, 000, ...}`이다. 언어 L은 그중 일부를 선택한 Σ\*의 부분집합으로, `L = {0ⁿ1ⁿ, n ≥ 0} = {ε, 01, 0011, 000111, ...}`처럼 정의할 수 있다.

## Chomsky Hierarchy (촘스키 위계)

촘스키 위계는 Noam Chomsky가 1956년에 제안한 분류 체계다. 문법의 생성 규칙(Production Rules)에 어떤 제약을 두는지에 따라 언어를 네 가지 타입으로 나누며, 각 타입은 이를 인식하는 기계 모델과 대응한다.

| 타입 | 언어 | 인식 기계 |
| --- | --- | --- |
| Type 0 | Recursively Enumerable | 튜링 기계 |
| Type 1 | Context-Sensitive | 선형 유계 오토마타 |
| Type 2 | Context-Free | 푸시다운 오토마타 |
| Type 3 | Regular | 유한 오토마타 |

## Type 3: 정규 언어 (Regular Language)

- 문법 형태: A → aB 또는 A → a (우선형) 또는 A → Ba 또는 A → a (좌선형)
- A, B: 비단말 기호 (Non-terminal)
- a: 단말 기호 (Terminal)

- 인식 기계: 유한 오토마타 (Finite Automata, FA)

유한 오토마타는 별도의 기억 공간 없이 현재 상태로 다음 동작을 결정한다. 정규 언어는 정규 표현식(Regular Expression)으로도 나타낼 수 있어, 컴파일러가 토큰을 인식하는 어휘 분석(Lexical Analysis)에 사용한다.

- 예시:
- L = {aⁿ, n ≥ 0}, // a의 임의 개수: 정규 언어 가능
- L = {ab, aabb, aaabbb, ...} // aⁿbⁿ: 정규 언어 불가 (짝을 맞춰야 함)
- `L = {w | w는 짝수 개의 0을 포함} // 정규 언어에 해당함`

- 정규 표현식 예시:
- (a b)\*, // {ε, a, b, aa, ab, ba, bb, aaa, ...}
- a\*b\*, // {ε, a, b, aa, ab, bb, aab, abb, ...}
- (ab)\*, // {ε, ab, abab, ababab, ...}
- [0-9]+, // 하나 이상의 숫자
- [a-zA-Z_][a-zA-Z0-9_]\*, // 식별자 패턴

## Type 2: 문맥 자유 언어 (Context-Free Language)

- 문법 형태: A → α
- A: 단일 비단말 기호
- α: 단말/비단말의 임의 조합 (빈 문자열 ε 포함 가능)

- 인식 기계: 푸시다운 오토마타 (Pushdown Automata, PDA)

푸시다운 오토마타는 스택을 사용하므로 괄호 매칭처럼 중첩된 구조를 처리할 수 있다. 이 성질 때문에 문맥 자유 언어는 프로그래밍 언어의 구문 분석에 쓰인다.

- 예시:
- // 괄호 매칭
- `S → (S) | SS | ε`
- // aⁿbⁿ 언어
- `S → aSb | ε`
- 생성 과정: S → aSb → aaSbb → aaabbb
- // 산술 표현식
- `E → E + T | T`
- `T → T * F | F`
- `F → (E) | id`

`aⁿbⁿ`을 인식하려면 먼저 나온 a의 개수를 기억해 뒤의 b와 맞춰야 한다. 유한 오토마타는 상태 수가 유한하므로 제한 없이 커지는 n을 모두 구분할 수 없다. 이 한계는 뒤에서 Pumping Lemma로 확인한다.

## Type 1: 문맥 의존 언어 (Context-Sensitive Language)

- 문법 형태: αAβ → αγβ
- |αAβ| ≤ |αγβ| (생성 규칙의 결과가 원본보다 짧아지면 안 됨)
- A가 특정 문맥(α, β) 안에서만 γ로 대체됨

- 인식 기계: 선형 유계 오토마타 (Linear Bounded Automata, LBA)

- 특징:
- 입력 길이에 비례하는 테이프만 사용하는 튜링 기계
- 자연어의 많은 특성을 표현 가능

- 예시:
- L = {aⁿbⁿcⁿ, n ≥ 1}, // 문맥 의존 언어
- // 문맥 자유 문법으로 불가능한 이유:
- // 스택 하나로는 세 종류(a, b, c)의 개수를 동시에 맞출 수 없음
- 문법 규칙 예시:
- `S → aSBC | aBC`
- CB → BC, // 문맥 의존: C가 B 앞에 있을 때만 교환
- aB → ab
- bB → bb
- bC → bc
- cC → cc

## Type 0: 재귀 열거 가능 언어 (Recursively Enumerable Language)

- 문법 형태: α → β (제약 없음)
- α는 최소 하나의 비단말 포함
- β는 어떤 것이든 가능 (ε 포함)

- 인식 기계: 튜링 기계 (Turing Machine)

- 특징:
- 가장 강력한 계산 모델
- 정지 문제(Halting Problem) 등 결정 불가능한 문제 존재
- 언어가 속하면 튜링 기계가 "멈추며 수락", 속하지 않으면 "영원히 실행되거나 거부"

## 언어 타입별 비교표

- 타입: Type 3:
  - 언어 종류: 정규
  - 문법 규칙: A → aB, A → a
  - 인식 기계: DFA/NFA
  - 폐쇄 특성: 합집합, 교집합, 여집합, 연결, \*
  - 예시: 식별자, 숫자 리터럴
- 타입: Type 2:
  - 언어 종류: 문맥 자유
  - 문법 규칙: A → α
  - 인식 기계: PDA
  - 폐쇄 특성: 합집합, 연결, \*
  - 예시: 프로그래밍 언어 구문
- 타입: Type 1:
  - 언어 종류: 문맥 의존
  - 문법 규칙: αAβ → αγβ
  - 인식 기계: LBA
  - 폐쇄 특성: 합집합, 교집합, 연결, \*
  - 예시: aⁿbⁿcⁿ
- 타입: Type 0:
  - 언어 종류: 재귀 열거
  - 문법 규칙: α → β
  - 인식 기계: TM
  - 폐쇄 특성: 합집합, 교집합, 연결, \*
  - 예시: 정지하는 프로그램

## Pumping Lemma

Pumping Lemma는 특정 언어가 정규 언어나 문맥 자유 언어가 아님을 증명할 때 쓰인다. 아래에서는 정규 언어가 만족해야 하는 조건을 가정한 뒤, `aⁿbⁿ`이 그 조건과 모순됨을 보인다.

- 정규 언어의 Pumping Lemma:
- L이 정규 언어이면, 어떤 pumping length p가 존재하여
- `|w| ≥ p인 모든 w ∈ L에 대해 w = xyz로 분할 가능하고:`
- `|y| > 0`
- `|xy| ≤ p`
- 모든 i ≥ 0에 대해 xyⁱz ∈ L

L = {aⁿbⁿ}이 정규 언어이고 pumping length가 p라고 가정하자. `w = aᵖbᵖ`를 고르면 `|w| = 2p ≥ p`이므로 위 조건을 만족하는 `w = xyz` 분할이 있어야 한다.

`|xy| ≤ p`이므로 x와 y에는 a만 들어가고, `|y| > 0`이므로 `y = aᵏ (k > 0)`이다. 그런데 y를 두 번 반복하면 `xy²z = aᵖ⁺ᵏbᵖ`가 된다. `p + k ≠ p`이므로 이 문자열은 L에 속하지 않아 세 번째 조건과 모순된다. 따라서 L은 정규 언어가 아니다.

## 프로그래밍 언어와 형식 언어

프로그래밍 언어를 분석할 때는 단계마다 필요한 구조가 다르다. 어휘 분석(Lexical Analysis)은 정규 언어로 식별자·숫자·키워드 같은 토큰을 인식한다. 구문 분석(Syntax Analysis)은 문맥 자유 언어로 표현식·문장·함수 정의의 구조를 분석한다. 이후 의미 분석(Semantic Analysis)에서는 변수 선언 여부와 타입처럼 문맥이 필요한 조건을 검사한다.

- 예시: C 언어 식별자

```c
// 정규 표현식으로 표현
[a-zA-Z_][a-zA-Z0-9_]*

// Type 3 문법
<identifier> → <letter> <id_tail>
<id_tail> → <letter> <id_tail> | <digit> <id_tail> | ε
<letter> → a | b | ... | z | A | ... | Z | _
<digit> → 0 | 1 | ... | 9
```

- 예시: 산술 표현식 (문맥 자유 문법)
- `<expr>` → `<expr>` + `<term>`, `<term>`
- `<term>` → `<term>` \* `<factor>`, `<factor>`
- `<factor>` → ( `<expr>` ), `<number>`, `<identifier>`
