# 파싱 이론

어휘 분석이 개별 토큰을 구분했다면, 파싱(Parsing)은 그 토큰의 순서가 문법에 맞는지 판단하고 구문 구조를 만든다. 이 과정에서 토큰 사이의 포함 관계와 결합 순서를 결정한다. 이름의 선언 여부나 타입의 호환성은 구문만으로 보장할 수 없으므로 후속 의미 분석에서 검사한다.

## 파싱의 두 가지 방향

하향식 파싱(Top-Down Parsing)은 시작 기호에서 출발해 앞으로 나올 입력을 예측하고 생성 규칙을 확장한다. 최좌단 유도를 구성하며, 재귀 하강 파서와 LL 파서가 대표적이다. 비단말과 함수의 대응이 명확해 직접 구현하기 쉽다.

상향식 파싱(Bottom-Up Parsing)은 읽은 입력을 문법의 우변으로 인식한 뒤 좌변 비단말로 축약한다. LR 계열의 Shift-Reduce 파서가 대표적이며, 최우단 유도의 역순을 구성한다. LL보다 넓은 문법 범위를 처리할 수 있지만 상태와 테이블을 만드는 과정이 복잡하다.

두 방식은 좌재귀 처리에서도 차이가 난다. 단순한 예측적 하향식 파서는 좌재귀를 직접 처리하지 못한다. LR 파서는 처리할 수 있지만, 모든 문맥 자유 문법을 충돌 없이 처리하는 것은 아니다.

## Top-Down 파싱

하향식 파서는 현재 확장할 비단말과 다음 입력 토큰을 바탕으로 생성 규칙을 선택한다. 선택한 우변을 순서대로 처리하면서 단말은 실제 입력과 비교하고, 비단말은 다시 확장한다.

여러 대안의 시작 부분이 같으면 다음 토큰 하나로 규칙을 고르기 어렵다. 이때는 공통 접두사를 분리하는 좌인수분해로 선택 시점을 늦출 수 있다. 좌재귀 규칙은 입력을 소비하기 전에 같은 함수를 반복 호출하게 하므로, 일반적인 예측적 재귀 하강에서는 제거해야 한다. 문법을 변환할 때는 인식하는 문자열뿐 아니라 AST에 담기는 연산자의 우선순위와 결합성도 보존해야 한다.

## Recursive Descent Parser (재귀 하강 파서)

재귀 하강 파서는 비단말마다 함수를 둔다. 규칙 우변의 비단말은 함수 호출로, 단말은 토큰 검사와 소비로 구현한다. 대안은 분기문으로, 반복은 반복문이나 재귀로 옮길 수 있다. 표현식의 우선순위별로 함수를 나누면 낮은 우선순위의 함수가 높은 우선순위의 구문을 호출하는 구조가 된다.

예측적 재귀 하강은 룩어헤드(Lookahead)로 대안을 선택해 되돌아가기를 피한다. 되돌아가기를 사용하는 구현은 입력 위치와 중간 결과를 복원해야 하고, 공통 접두사를 반복해서 분석하면 비용도 커질 수 있다.

각 함수는 분석 결과를 AST 노드로 반환할 수 있다. 입력 전체를 처리하는 진입점에서는 노드를 만들었다는 사실만으로 성공 처리하지 않고, 남은 토큰 없이 입력 끝에 도달했는지도 확인해야 한다.

## LL(1) 파서

LL(1)의 첫 번째 L은 입력을 왼쪽에서 오른쪽으로 읽는다는 뜻이고, 두 번째 L은 최좌단 유도를 구성한다는 뜻이다. 1은 생성 규칙을 결정할 때 다음 입력 토큰 하나를 사용한다는 의미다. 입력을 소비할 때마다 룩어헤드도 갱신된다.

파서는 스택의 비단말과 룩어헤드를 키로 테이블을 조회한다. 각 칸에 규칙이 하나 이하라면 되돌아가지 않고 규칙을 선택할 수 있다. 이 선택 원리는 테이블로 구현할 수도, 예측적 재귀 하강 함수로 구현할 수도 있다.

## First 집합 계산

`FIRST(α)`는 기호열 `α`에서 유도할 수 있는 문자열의 첫 단말을 모은 집합이다. 빈 문자열을 유도할 수 있으면 `ε`도 포함한다. 단말의 FIRST에는 그 단말 자체가 들어가고, 빈 기호열의 FIRST는 `{ε}`다.

기호열의 FIRST는 왼쪽부터 각 기호의 FIRST에서 `ε`를 제외한 단말을 합쳐 구한다. 현재 기호가 빈 문자열을 만들 수 있을 때만 다음 기호로 진행한다. 모든 기호가 빈 문자열을 만들 수 있다면 전체 기호열의 FIRST에도 `ε`를 추가한다.

비단말에 여러 생성 규칙이 있으면 각 우변의 FIRST를 합친다. 규칙 사이에 상호 참조가 있으므로 새 원소가 추가되지 않을 때까지 계산을 반복한다.

## Follow 집합 계산

`FOLLOW(A)`는 유도 과정의 문장 형식에서 비단말 `A` 바로 뒤에 올 수 있는 단말의 집합이다. 시작 기호의 FOLLOW에는 입력 끝 표시 `$`를 넣는다.

`B → α A β`에서는 `FIRST(β)`에서 `ε`를 제외한 단말을 `FOLLOW(A)`에 추가한다. `β`가 비어 있거나 빈 문자열을 유도할 수 있다면 B 뒤에 오는 단말도 A 뒤에 올 수 있으므로 `FOLLOW(B)`를 함께 추가한다. 이 전파를 변화가 없을 때까지 반복하며, FOLLOW에는 `ε`를 넣지 않는다.

## LL(1) 문법 조건

LL(1) 문법에서는 같은 비단말의 각 대안을 선택하는 룩어헤드 집합이 서로 겹치지 않아야 한다. 규칙 `A → α`의 선택 집합은 `FIRST(α) - {ε}`이고, `α`가 빈 문자열을 유도할 수 있으면 `FOLLOW(A)`도 포함한다.

서로 다른 두 규칙의 선택 집합이 겹치면 같은 비단말과 입력 토큰으로 두 규칙이 후보가 되어 충돌한다. 서로 다른 대안이 같은 토큰으로 시작하면 FIRST/FIRST 충돌이고, 빈 문자열 대안을 선택하는 조건과 다른 대안을 시작하는 조건이 겹치면 FIRST/FOLLOW 충돌이다.

따라서 빈 문자열을 만드는 대안은 그 대안 자체의 FIRST와 FOLLOW만 비교해서는 안 된다. 다른 대안의 시작 토큰과 선택이 겹치는지도 검사해야 한다. [Stanford CS143 파싱 테이블 구성 규칙](https://cs143.stanford.edu/handouts/cs143_midterm2024_sol.pdf)에서도 이 조건을 확인할 수 있다. 좌재귀 제거와 좌인수분해를 적용했더라도 LL(1) 조건은 별도로 확인해야 한다.

## LL(1) 파싱 테이블 구성 알고리즘

먼저 FIRST와 FOLLOW를 계산한다. 이어서 각 규칙의 선택 집합에 속하는 토큰마다 해당 비단말의 테이블 칸에 규칙을 넣는다.

이미 다른 규칙이 있는 칸에 새 규칙을 넣어야 한다면 충돌을 보고한다. 나중 규칙으로 덮어쓰면 문법의 문제가 가려진다. 반대로 규칙이 없는 칸은 해당 상태에서 허용되지 않는 입력을 뜻하므로 구문 오류로 처리한다.

## 예측적 파싱 알고리즘

스택에 입력 끝 표시와 시작 기호를 넣고 첫 룩어헤드를 준비한 뒤, 스택 맨 위 기호에 따라 처리한다.

1. 단말이면 룩어헤드와 비교한다. 일치하면 스택에서 제거하고 입력 토큰 하나를 소비한다.
2. 비단말이면 테이블에서 규칙을 선택한다. 우변의 첫 기호부터 처리할 수 있도록 역순으로 스택에 넣는다.
3. 빈 문자열 규칙을 선택했다면 비단말만 제거하고 입력은 소비하지 않는다.

스택과 입력이 모두 끝 표시에 도달해야 수락한다. 스택만 비었거나 입력이 남은 상태는 성공이 아니다. 고정된 LL(1) 문법과 정상적인 테이블 구현에서는 입력 토큰 수에 따른 처리 비용을 선형으로 볼 수 있으며, 문법 분석과 테이블 생성 비용은 별도로 계산한다.

## 파서 에러 복구

구문 오류를 진단하려면 오류 위치, 실제 토큰, 기대한 토큰 집합을 함께 기록하는 것이 좋다. 이후 분석을 이어가는 방법으로 패닉 모드(Panic Mode)와 구문 단위 복구가 있다.

패닉 모드는 문장 경계나 닫는 구분자 같은 동기화 토큰까지 입력을 건너뛴다. 구문 단위 복구는 제한된 토큰 삽입·삭제·교체를 시도한다. 잘못된 복구가 후속 오류를 늘릴 수 있으므로 적용 범위를 제한해야 한다.

어느 방식이든 입력을 소비하거나 스택을 줄이면서 진행해야 하고, 입력 끝에서도 종료할 수 있어야 한다. 복구한 AST에 오류 노드를 남기면 후속 단계가 정상 구문과 구별할 수 있다.

## LL(k) 및 LL(*) 파싱

LL(k)는 고정된 수 `k`개의 룩어헤드 토큰으로 대안을 선택한다. 더 긴 접두사를 구별할 수 있지만 판단 구조가 커질 수 있다. LL(\*)는 필요에 따라 가변 길이의 룩어헤드를 사용하며, 무한히 많은 입력을 미리 읽는다는 뜻은 아니다.

구현 도구의 지원 범위는 일반적인 LL 이론과 구분해야 한다. 특정 생성기가 좌재귀를 지원하더라도 단순한 재귀 하강 함수가 좌재귀를 그대로 처리할 수 있는 것은 아니다.
