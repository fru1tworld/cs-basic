# 어휘 분석

어휘 분석(Lexical Analysis)은 소스 코드의 문자 스트림에서 패턴을 인식해 토큰(Token)을 만드는 과정이다. 컴파일러의 첫 단계에서 수행하며, 이를 담당하는 모듈을 Lexer, Scanner 또는 Tokenizer라고 한다.

## 컴파일러 전단부에서의 위치

Lexer가 소스 코드를 토큰 스트림으로 바꾸면, Parser는 그 토큰들의 구조를 분석해 AST를 만든다. 예를 들어 `if (x > 0)`은 `[IF][LPAREN][ID:x][GT][NUM:0][RPAREN]`으로 나뉜 뒤 구문 분석기로 전달된다.

이렇게 단계를 나누면 문자 처리와 구조 분석을 분리할 수 있다. 정규 언어로 처리할 수 있는 토큰 인식에는 빠른 분석 방법을 쓰고, 더 복잡한 문맥 자유 언어의 구조 분석은 Parser에 맡긴다. 문자 인코딩 처리도 Lexer 한곳에 모을 수 있다.

## 토큰 (Token)

토큰은 어휘 분석의 출력 단위로, 타입과 속성값으로 구성된다. 타입은 식별자·숫자·문자열 같은 분류를 나타내고, 속성값은 이름이나 실제 값을 담는다.

- IDENTIFIER:
  - 속성값(옵션): "count"
- NUMBER:
  - 속성값(옵션): 42
- STRING:
  - 속성값(옵션): "hello"
- KEYWORD:
  - 속성값(옵션): (if, while 등)
- OPERATOR:
  - 속성값(옵션): +, -, \*, /
- DELIMITER:
  - 속성값(옵션): (, ), {, }, ;

패턴은 토큰을 정의하는 규칙이고, 렉심(Lexeme)은 그 패턴에 일치하는 실제 문자열이다. 식별자 패턴 `[a-zA-Z_][a-zA-Z0-9_]*`에는 `"count"`, `"total"`, `"MAX_SIZE"` 같은 렉심이 일치한다. Lexer는 이를 `(IDENTIFIER, "count")`, `(IDENTIFIER, "total")` 같은 토큰으로 만든다.

## 토큰 종류

```java
public enum TokenType {
    // 키워드
    IF, ELSE, WHILE, FOR, RETURN, CLASS, PUBLIC, PRIVATE,

    // 리터럴
    INTEGER_LITERAL,    // 42, 0xFF, 0b1010
    FLOAT_LITERAL,      // 3.14, 1.0e-10
    STRING_LITERAL,     // "hello"
    CHAR_LITERAL,       // 'a'
    BOOLEAN_LITERAL,    // true, false

    // 식별자
    IDENTIFIER,         // variable, functionName

    // 연산자
    PLUS, MINUS, STAR, SLASH,           // + - * /
    EQ, NE, LT, GT, LE, GE,             // == != < > <= >=
    AND, OR, NOT,                        // && || !
    ASSIGN,                              // =
    PLUS_ASSIGN, MINUS_ASSIGN,          // += -=

    // 구분자
    LPAREN, RPAREN,     // ( )
    LBRACE, RBRACE,     // { }
    LBRACKET, RBRACKET, // [ ]
    SEMICOLON,          // ;
    COMMA,              // ,
    DOT,                // .

    // 특수
    EOF,                // 파일 끝
    NEWLINE,            // 줄바꿈 (Python 등)
    INDENT, DEDENT,     // 들여쓰기 (Python)
}
```

## Lexer 동작 원리

- 입력: "if (count >= 10) {"
- Lexer 처리 과정
- 위치, 현재 문자, 동작, 결과
- 0, 'i', 식별자/키워드 시작
- 1, 'f', 계속 읽기
- 2, ' ', 끝 → 키워드 "if" 확인, IF
- 3, '(', 단일 문자 토큰, LPAREN
- 4, 'c', 식별자 시작
- ..., ..., "count" 읽기
- 9, ' ', 끝, ID:count
- 10, '>', 연산자 시작
- 11, '=', '>=' 확인, GE
- 12, ' ', 공백 스킵
- 13, '1', 숫자 시작
- 14, '0', 계속 읽기
- 15, ')', 끝, NUM:10
- 16, ')', 단일 문자 토큰, RPAREN
- 17, ' ', 공백 스킵
- 18, '{', 단일 문자 토큰, LBRACE
- 출력 토큰 스트림:
- [IF] [LPAREN] [IDENTIFIER:"count"] [GE] [INTEGER:10] [RPAREN] [LBRACE]

## Maximal Munch (최대 일치 원칙)

최대 일치 원칙은 현재 위치에서 가능한 가장 긴 토큰을 선택하는 규칙이다. 여러 문자로 된 연산자가 있을 때 문자를 하나씩 토큰으로 나누지 않도록 한다.

- 입력: " x"
- Maximal Munch 적용:
- "++" 인식 → INCREMENT
- "++" 인식 → INCREMENT
- "+" 인식 → PLUS
- "x" 인식 → IDENTIFIER
- 결과: ++ ++ + x
- 의미: ((++)(++))(+x) → 전위 증가 두 번 후 x에 더함
- Maximal Munch 없이 (첫 번째 매치 선택):
- 결과: + + + + + x
- 의미: 완전히 다른 해석
- 실제 예시들:
- ">>>" → UNSIGNED_RIGHT_SHIFT (Java)
- vs ">" ">" ">" (제네릭과 섞일 때 문제)
- "<:" → SUBTYPE 연산자 (Scala)
- vs "<" ":" (비교 후 타입 지정)

## 예약어 처리

키워드(예약어)는 식별자와 같은 패턴에 일치하므로 추가로 구분해야 한다. 식별자 패턴을 읽은 뒤 키워드 테이블을 조회하거나, 키워드마다 별도 패턴과 우선순위를 지정하는 방식을 쓴다.

- 방법 1: 키워드 테이블 조회
- [a-zA-Z_][a-zA-Z0-9_]\* 패턴 매치
- 키워드 해시 테이블 조회
- 매치되면 KEYWORD, 아니면 ID
- public Token scanIdentifierOrKeyword() {
- String lexeme = scanWhile(c → isAlphanumeric(c), c == '_');
- // 키워드 테이블 조회 (해시맵 O(1))
- TokenType keyword = KEYWORDS.get(lexeme);
- if (keyword != null) {
- return new Token(keyword, lexeme);
- return new Token(IDENTIFIER, lexeme);
- private static final Map`<String, TokenType>` KEYWORDS = Map.of(
- "if", IF
- "else", ELSE
- "while", WHILE
- "for", FOR
- "return", RETURN
- 방법 2: 별도 DFA 상태 (Flex/Lex 방식)
- 각 키워드에 대해 명시적 패턴
- 키워드 패턴이 식별자보다 먼저 매칭되도록 우선순위 지정

- [0-9]\* "." [0-9]+ ([eE][+-]?[0-9]+)?
- [0-9]+ [eE][+-]?[0-9]+

## Flex/Lex 사용

Flex/Lex에는 패턴과 그 패턴을 인식했을 때 실행할 동작을 함께 적는다. 아래 예제는 공백과 주석을 건너뛰고, 숫자·식별자·연산자 등을 읽으면 해당 토큰을 반환한다.

```lex
/* 토큰 정의 - calculator.l */
%{
#include "y.tab.h"  /* 파서가 생성한 토큰 정의 */
%}

%%

[ \t\n]+        { /* 공백 무시 */ }
"//"[^\n]*      { /* 한 줄 주석 무시 */ }

[0-9]+          { yylval.num = atoi(yytext); return NUMBER; }
[0-9]+\.[0-9]+  { yylval.fnum = atof(yytext); return FLOAT; }

"if"            { return IF; }
"else"          { return ELSE; }
"while"         { return WHILE; }
"return"        { return RETURN; }

[a-zA-Z_][a-zA-Z0-9_]* { yylval.str = strdup(yytext); return IDENTIFIER; }

"+"             { return PLUS; }
"-"             { return MINUS; }
"*"             { return STAR; }
"/"             { return SLASH; }
"=="            { return EQ; }
"!="            { return NE; }
"<="            { return LE; }
">="            { return GE; }
"<"             { return LT; }
">"             { return GT; }
"="             { return ASSIGN; }

"("             { return LPAREN; }
")"             { return RPAREN; }
"{"             { return LBRACE; }
"}"             { return RBRACE; }
";"             { return SEMICOLON; }
","             { return COMMA; }

.               { printf("Unknown character: %s\n", yytext); }

%%

int yywrap() { return 1; }
```

## 에러 복구

알 수 없는 문자를 만나면 오류 위치를 기록하고 분석을 이어갈 지점을 찾아야 한다. 아래 구현은 다음 공백이나 알려진 시작 문자까지 건너뛴 뒤 오류 토큰을 반환해 Parser가 처리하도록 한다.

```java
public class Lexer {
    public Token nextToken() {
        skipWhitespaceAndComments();

        if (isAtEnd()) {
            return new Token(EOF, "", line, column);
        }

        char c = peek();

        // 숫자
        if (isDigit(c)) return scanNumber();

        // 식별자 / 키워드
        if (isAlpha(c) || c == '_') return scanIdentifier();

        // 문자열
        if (c == '"' || c == '\'') return scanString();

        // 연산자와 구분자
        Token op = scanOperator();
        if (op != null) return op;

        // 에러 복구: 알 수 없는 문자
        return errorToken("Unexpected character: " + c);
    }

    private Token errorToken(String message) {
        // 에러 보고
        errors.add(new LexicalError(message, line, column));

        // Panic Mode: 다음 공백이나 알려진 문자까지 스킵
        while (!isAtEnd() && !isWhitespace(peek()) && !isKnownStart(peek())) {
            advance();
        }

        // 에러 토큰 반환 (파서에서 처리)
        return new Token(ERROR, message, line, column);
    }
}
```
