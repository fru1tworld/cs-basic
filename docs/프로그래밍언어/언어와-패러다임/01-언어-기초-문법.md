# 언어 기초 문법

## 타입 시스템

### Static vs Dynamic Typing

#### Static Typing (정적 타입)

정적 타입 언어는 컴파일 타임에 변수의 타입을 결정한다. 따라서 아래 Java 예제처럼 정수 변수에 문자열을 대입하면 컴파일 단계에서 타입 불일치를 발견한다. Go 예제는 타입을 명시하지 않아도 컴파일러가 타입을 추론하는 경우를 보여준다.

```java
// Java - 정적 타입 언어
public class StaticTypingExample {
    public static void main(String[] args) {
        String name = "John";
        int age = 25;

        // 컴파일 에러: incompatible types
        // age = "twenty-five";

        // 제네릭을 통한 타입 안정성
        List<String> names = new ArrayList<>();
        names.add("Alice");
        // names.add(123); // 컴파일 에러
    }
}
```

```go
// Go - 정적 타입 + 타입 추론
package main

func main() {
    // 타입 추론 (컴파일 타임에 타입 결정)
    name := "John"  // string으로 추론
    age := 25       // int로 추론

    // 명시적 타입 선언
    var salary float64 = 50000.0

    // 컴파일 에러: cannot use "25" (type string) as type int
    // age = "25"
}
```

컴파일 타임에 확보한 타입 정보는 오류 발견뿐 아니라 IDE의 자동완성·리팩토링과 실행 성능 최적화에도 쓰인다. 타입 선언 자체가 코드를 설명하는 역할도 한다. 다만 타입을 표현하기 위한 반복 코드가 늘 수 있고, 구조가 동적으로 바뀌는 데이터를 다룰 때는 유연성이 줄어든다.

#### Dynamic Typing (동적 타입)

동적 타입 언어에서는 같은 변수에 다른 타입의 값을 할당할 수 있다. 아래 Python 예제의 `value`는 실행 중 문자열, 정수, 리스트를 차례로 가리킨다. 이어지는 Duck Typing 예제에서는 객체의 타입을 직접 검사하지 않고 필요한 메서드를 호출한다.

```python
# Python - 동적 타입 언어
def dynamic_example():
    value = "Hello"  # str
    print(type(value))  # <class 'str'>

    value = 42  # int로 변경
    print(type(value))  # <class 'int'>

    value = [1, 2, 3]  # list로 변경
    print(type(value))  # <class 'list'>

# Duck Typing 예제
class Duck:
    def quack(self):
        print("Quack!")

    def walk(self):
        print("Walking like a duck")

class Person:
    def quack(self):
        print("I'm quacking like a duck!")

    def walk(self):
        print("Walking like a person")

def make_it_quack(thing):
    # 타입을 검사하지 않고 메서드만 호출
    thing.quack()
    thing.walk()

make_it_quack(Duck())    # OK
make_it_quack(Person())  # OK - Duck이 아니어도 동작
```

이 방식은 코드를 간결하게 작성하고 빠르게 프로토타입을 만들기 좋으며, Duck Typing으로 유연한 다형성을 구현할 수 있다. 반면 실행 중에야 드러나는 타입 오류가 생길 수 있다. 리팩토링이 어려워지거나 대규모 프로젝트의 유지보수 비용이 늘어나는 점도 고려해야 한다.

### Strong vs Weak Typing

#### Strong Typing (강타입)

강타입은 암묵적 타입 변환을 허용하지 않거나 제한적으로 허용하는 특성을 가리킨다. 아래 Python 예제에서는 정수를 문자열로 직접 바꿔야 연결할 수 있다. Java 예제는 확장 변환을 허용하지만 축소 변환에는 명시적인 캐스팅을 요구하는 경우를 보여준다.

```python
# Python - 강타입 언어
number = 42
text = "The answer is: "

# TypeError: can only concatenate str (not "int") to str
# result = text + number

# 명시적 변환 필요
result = text + str(number)  # OK
```

```java
// Java - 강타입 (일부 암묵적 변환 허용)
public class StrongTyping {
    public static void main(String[] args) {
        int intValue = 42;
        long longValue = intValue;  // OK - 확장 변환 (Widening)

        long bigValue = 100L;
        // int smallValue = bigValue;  // 컴파일 에러 - 축소 변환 불가
        int smallValue = (int) bigValue;  // 명시적 캐스팅 필요

        String text = "Number: " + intValue;  // OK - 문자열 연결 시 자동 변환
    }
}
```

#### Weak Typing (약타입)

약타입은 암묵적 타입 변환을 폭넓게 허용한다. 아래 JavaScript 예제에서는 같은 문자열 `"5"`도 연산자에 따라 문자열 연결에 쓰이거나 숫자로 변환된다.

```javascript
// JavaScript - 약타입 언어
console.log("5" + 3);      // "53" (문자열 연결)
console.log("5" - 3);      // 2 (숫자 연산)
console.log("5" * "2");    // 10 (숫자 연산)
console.log(true + true);  // 2
console.log([] + {});      // "[object Object]"
console.log({} + []);      // 0 또는 "[object Object]" (환경에 따라 다름)

// 동등 연산자의 타입 강제 변환
console.log("5" == 5);     // true (타입 강제 변환)
console.log("5" === 5);    // false (엄격한 비교)
console.log(null == undefined);  // true
console.log(null === undefined); // false
```

## 메모리 모델

### Stack vs Heap

#### Stack 메모리

- Stack Memory
- Function Call Frame, ← Top (SP: Stack Pointer)
- Local Variables
- Return Address
- Parameters
- Previous Function Frame
- Main Function Frame, ← Bottom
- ↑ 성장 방향 (높은 주소 → 낮은 주소)

- 특징:
- LIFO (Last In First Out) 구조
- 컴파일 타임에 크기가 결정됨
- 매우 빠른 할당/해제 (포인터 이동만으로 가능)
- 함수 호출 시 자동 생성, 반환 시 자동 해제
- 크기 제한 있음 (일반적으로 1~8MB)

```java
// Java - Stack에 저장되는 데이터
public class StackExample {
    public static void main(String[] args) {
        int x = 10;           // Stack: primitive
        double y = 20.5;      // Stack: primitive

        calculate(x, y);      // 새 Stack Frame 생성
    }

    public static double calculate(int a, double b) {
        int result = a * 2;   // Stack: 지역 변수
        return result + b;
    }  // 함수 종료 시 Stack Frame 제거
}
```

```c
// C - Stack과 함수 호출
#include <stdio.h>

void recursive(int n) {
    int local_array[1000];  // Stack에 4KB 할당
    printf("Depth: %d, Address: %p\n", n, (void*)&local_array);

    if (n > 0) {
        recursive(n - 1);  // Stack 계속 성장
    }
}

int main() {
    recursive(10);  // Stack Overflow 가능
    return 0;
}
```

#### Heap 메모리

- Heap Memory
- Object1, Object2
- 100B, 500B, Free
- Object3, Free
- 1KB
- Free Space
- ↓ 성장 방향 (낮은 주소 → 높은 주소)

- 특징:
- 동적 메모리 할당
- 런타임에 크기 결정 가능
- 프로그래머 또는 GC가 명시적으로 관리
- Stack보다 느린 할당/해제
- 단편화(Fragmentation) 발생 가능

```java
// Java - Heap에 저장되는 데이터
public class HeapExample {
    public static void main(String[] args) {
        // 객체는 Heap에 저장, 참조는 Stack에 저장
        String name = new String("Hello");  // Heap: "Hello" 객체
        int[] array = new int[1000];        // Heap: 배열 객체

        Person person = new Person("John", 25);  // Heap: Person 객체

        // Stack: name, array, person (참조 변수들)
        // Heap: String 객체, int[] 객체, Person 객체
    }
}

class Person {
    private String name;  // Heap 내 객체의 필드
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```go
// Go - Escape Analysis
package main

// 컴파일러가 스택 vs 힙 할당을 결정
func stackAllocation() int {
    x := 42  // 스택에 할당 (함수 내에서만 사용)
    return x
}

func heapAllocation() *int {
    x := 42   // 힙에 할당 (함수 외부로 escape)
    return &x // 주소를 반환하므로 힙 할당
}

// go build -gcflags="-m" 으로 escape analysis 확인 가능
```

### 메모리 레이아웃

- High Address
- Kernel Space, (운영체제 영역)
- Stack, ↓ 성장
- (지역 변수, 매개변수)
- (사용 가능 공간)
- Heap, ↑ 성장
- (동적 할당)
- BSS Segment, (초기화되지 않은 전역/정적 변수)
- Data Segment, (초기화된 전역/정적 변수)
- Text Segment, (기계어 코드, Read-Only)
- Low Address

## 가비지 컬렉션

### 가비지 컬렉션 개요

가비지 컬렉션(GC)은 더 이상 사용되지 않는 메모리를 자동으로 회수한다. 여기서는 루트 집합(Root Set)에서 객체에 도달할 수 있는지를 기준으로 회수 대상을 구분한다.

예를 들어 스택의 변수가 A를, A가 B를, B가 C를 참조한다면 A·B·C는 도달 가능한 객체다. 정적 변수가 참조하는 D도 마찬가지다. 반면 E가 F를 참조하더라도 루트에서 E와 F에 도달할 수 없다면 둘 다 가비지에 해당한다.

### Mark-and-Sweep 알고리즘

#### Phase 1: Mark (마킹)

루트 집합에서 시작해 참조를 따라가며 도달 가능한 객체를 마킹한다. 앞의 예에서는 스택 변수에서 이어지는 A·B·C가 마킹되고, 도달할 수 없는 E와 F는 마킹되지 않는다.

#### Phase 2: Sweep (스윕)

마킹을 마치면 힙을 훑으며 마킹되지 않은 객체를 해제한다. A·B·C는 남고 E와 F가 차지하던 영역은 빈 공간이 된다. 아래 의사 코드는 이 두 단계를 나누어 보여준다.

```java
// Mark-and-Sweep 의사 코드
public class MarkAndSweep {
    private Set<Object> marked = new HashSet<>();

    // Mark Phase
    public void mark(Object root) {
        if (root == null || marked.contains(root)) {
            return;
        }
        marked.add(root);

        // 객체가 참조하는 모든 객체를 재귀적으로 마킹
        for (Object reference : getReferences(root)) {
            mark(reference);
        }
    }

    // Sweep Phase
    public void sweep(List<Object> allObjects) {
        Iterator<Object> iterator = allObjects.iterator();
        while (iterator.hasNext()) {
            Object obj = iterator.next();
            if (!marked.contains(obj)) {
                // 마킹되지 않은 객체 해제
                free(obj);
                iterator.remove();
            }
        }
        marked.clear();  // 다음 GC 사이클을 위해 초기화
    }
}
```

이 방식은 전체 힙을 스캔해야 하며, GC 실행 중 애플리케이션을 멈추는 Stop-the-World가 발생한다. 또한 객체를 해제한 자리가 흩어져 있어 메모리가 단편화될 수 있다.

### Mark-and-Compact 알고리즘

Mark-and-Compact는 살아 있는 객체를 모아 Mark-and-Sweep의 단편화 문제를 해결한다. 예를 들어 `A, Free, B, Free, C, Free`로 흩어져 있던 메모리를 `A, B, C, Free`로 정리해 연속된 빈 공간을 만든다.

### Generational GC (세대별 가비지 컬렉션)

- 약한 세대 가설 (Weak Generational Hypothesis):
- 대부분의 객체는 생성 직후 곧바로 사용되지 않게 됨 (Young Die Young)
- 오래된 객체가 새로운 객체를 참조하는 경우는 드묾

- Heap Memory
- Young Generation, Old Generation
- Eden, Survivor, Tenured Space
- Space, S0, S1
- 80%, 10%, 10%
- 객체 생성 → Eden → (살아남음) → Survivor → (나이 증가) → Old Gen

#### JVM의 세대별 GC

```java
// JVM GC 동작 이해를 위한 예제
public class GenerationalGCExample {
    public static void main(String[] args) {
        // 1. 새 객체는 Eden에 할당
        Object shortLived = new Object();  // Eden

        // 2. 짧은 수명 객체는 Minor GC에서 수집
        shortLived = null;

        // 3. 오래 살아남는 객체
        List<byte[]> longLived = new ArrayList<>();
        for (int i = 0; i < 100; i++) {
            // Survivor를 거쳐 Old Generation으로 이동
            longLived.add(new byte[1024 * 1024]);  // 1MB
        }

        // GC 로그 확인: -XX:+PrintGCDetails -XX:+PrintGCDateStamps
    }
}
```

#### GC 종류별 비교

- GC 종류: Serial GC:
  - Young Gen GC: Serial
  - Old Gen GC: Serial Mark-Sweep-Compact
  - 특징: 단일 스레드, 작은 힙
- GC 종류: Parallel GC:
  - Young Gen GC: Parallel Scavenge
  - Old Gen GC: Parallel Old
  - 특징: 멀티 스레드, 처리량 중시
- GC 종류: CMS:
  - Young Gen GC: ParNew
  - Old Gen GC: Concurrent Mark-Sweep
  - 특징: 낮은 지연시간 (Deprecated)
- GC 종류: G1 GC:
  - Young Gen GC: Mixed GC
  - Old Gen GC: Mixed GC
  - 특징: Region 기반, 균형잡힌 성능
- GC 종류: ZGC:
  - Young Gen GC: -
  - Old Gen GC: Concurrent
  - 특징: 매우 낮은 지연시간 (<10ms)
- GC 종류: Shenandoah:
  - Young Gen GC: -
  - Old Gen GC: Concurrent
  - 특징: 낮은 지연시간

### G1 GC (Garbage-First GC)

- G1 Heap Layout
- E, E, S, O, O, H, E, F
- O, F, F, O, E, H, S, O
- F, O, E, F, O, H, O, F
- E: Eden, S: Survivor, O: Old
- H: Humongous, F: Free

- 특징:
- Heap을 동일한 크기의 Region으로 분할
- 가비지가 많은 Region을 우선 수집 (Garbage-First)
- 예측 가능한 일시 정지 시간 (-XX:MaxGCPauseMillis)

```bash
# G1 GC JVM 옵션 예시
java -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -XX:G1HeapRegionSize=16m \
     -XX:InitiatingHeapOccupancyPercent=45 \
     -Xms4g -Xmx4g \
     MyApplication
```

### Go의 GC

- Go는 Tri-color Mark-and-Sweep 알고리즘을 사용함.

```go
// Go GC는 동시성 GC (Concurrent GC)
// - STW 시간 최소화 (보통 1ms 미만)
// - Write Barrier 사용

package main

import (
    "runtime"
    "runtime/debug"
)

func main() {
    // GC 통계 확인
    var stats debug.GCStats
    debug.ReadGCStats(&stats)

    // 수동 GC 트리거
    runtime.GC()

    // GC 비율 조정 (기본값: 100)
    // GOGC=200 이면 힙이 2배가 될 때 GC
    debug.SetGCPercent(200)
}
```

Tri-color Marking은 객체의 방문 상태를 세 가지 색으로 구분한다.

| 색 | 상태 |
| --- | --- |
| White | 아직 방문하지 않은 객체로, 수집 후보에 해당한다. |
| Gray | 발견했지만 참조하는 객체를 모두 조사하지 않은 상태다. |
| Black | 자신과 참조 관계의 조사가 끝난 상태다. |

처음에는 객체를 White로 두고 루트에서 도달한 객체를 Gray로 표시한다. Gray 객체의 참조 대상을 작업 목록에 추가한 뒤, 참조 조사를 마친 객체를 Black으로 바꾼다. 도달 가능한 객체의 조사를 모두 마쳤을 때도 White로 남아 있는 객체가 수집 대상이다.

## 컴파일 vs 인터프리터

### 컴파일러 (Compiler)

- 소스 코드 전체를 기계어로 변환한 후 실행함.

- Source Code, →, Compiler, →, Machine Code
- (\*.c, \*.go), (\*.exe, bin)
- Execution

#### 컴파일 과정

소스 코드는 분석, 중간 표현 생성, 최적화, 코드 생성 단계를 거친다.

1. 어휘 분석(Lexical Analysis)은 `int x = 42;`를 `[INT, ID(x), ASSIGN, NUM(42), SEMICOLON]` 같은 토큰으로 나눈다.
2. 구문 분석(Syntax Analysis)은 토큰의 구조를 분석해 추상 구문 트리(AST)를 만든다.
3. 의미 분석(Semantic Analysis)은 타입과 스코프를 검사한다.
4. LLVM IR이나 Java Bytecode 같은 중간 표현(IR)을 생성한다.
5. 인라이닝이나 루프 최적화 등을 수행한다.
6. 코드 생성(Code Generation) 단계에서 x86, ARM 등 대상 아키텍처의 기계어를 만든다.

```c
// C 컴파일 예시
// gcc -S -O2 example.c  (어셈블리 출력)
// gcc -c example.c      (오브젝트 파일)
// gcc example.c -o example (실행 파일)

int add(int a, int b) {
    return a + b;
}

int main() {
    int result = add(3, 5);
    return result;
}

// 생성된 x86-64 어셈블리 (최적화 전)
// add:
//     pushq   %rbp
//     movq    %rsp, %rbp
//     movl    %edi, -4(%rbp)
//     movl    %esi, -8(%rbp)
//     movl    -4(%rbp), %edx
//     movl    -8(%rbp), %eax
//     addl    %edx, %eax
//     popq    %rbp
//     ret
```

- 장점:
- 빠른 실행 속도
- 배포 시 소스 코드 노출 없음
- 컴파일 타임 최적화

- 단점:
- 플랫폼별 컴파일 필요
- 컴파일 시간 소요
- 디버깅이 상대적으로 어려움

### 인터프리터 (Interpreter)

- 소스 코드를 한 줄씩 읽어서 즉시 실행함.

- Source Code, →, Interpreter, → 실행 결과
- (\*.py)

```python
# Python 인터프리터 동작 예시
# 코드를 한 줄씩 읽고 실행

def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

# 이 시점에서 함수 정의가 해석되고 메모리에 저장됨
print(fibonacci(10))  # 이 줄이 실행될 때 함수 호출
```

- 장점:
- 빠른 개발 사이클 (수정 후 즉시 실행)
- 플랫폼 독립적
- 동적 코드 실행 가능 (eval, exec)
- 디버깅 용이

- 단점:
- 느린 실행 속도
- 런타임 에러
- 소스 코드 노출

### 하이브리드 방식

#### JIT (Just-In-Time) 컴파일

Java 소스 코드(`*.java`)는 `javac`를 거쳐 바이트코드(`*.class`)가 된다. JVM은 처음에는 인터프리터로 실행하다가 자주 실행되는 코드(Hot Code)를 JIT 컴파일러로 최적화한다. 아래 예제는 반복해서 호출하는 메서드가 그 대상이 되는 과정을 보여준다.

```java
// JIT 컴파일 예시
public class JITExample {
    public static void main(String[] args) {
        long sum = 0;

        // 처음에는 인터프리터로 실행
        // 반복이 많아지면 (threshold 도달) JIT 컴파일
        for (int i = 0; i < 100_000_000; i++) {
            sum += calculate(i);  // Hot Method
        }

        System.out.println(sum);
    }

    // 자주 호출되면 JIT 컴파일러가 네이티브 코드로 변환
    private static int calculate(int n) {
        return n * 2 + 1;
    }
}

// JIT 컴파일 확인: java -XX:+PrintCompilation JITExample
```

### 언어별 실행 방식 비교

- 언어: C/C++:
  - 실행 방식: 순수 컴파일
  - 특징: 네이티브 기계어, 최고 성능
- 언어: Go:
  - 실행 방식: 순수 컴파일
  - 특징: 단일 바이너리, 빠른 컴파일
- 언어: Rust:
  - 실행 방식: 순수 컴파일
  - 특징: LLVM 기반, 안전성 + 성능
- 언어: Java:
  - 실행 방식: 컴파일 + JIT
  - 특징: 바이트코드 → JVM → JIT
- 언어: Kotlin:
  - 실행 방식: 컴파일 + JIT
  - 특징: Java와 동일 (JVM) 또는 Native
- 언어: Python:
  - 실행 방식: 인터프리터
  - 특징: CPython (바이트코드 캐싱)
- 언어: JavaScript:
  - 실행 방식: JIT
  - 특징: V8, SpiderMonkey 등
- 언어: TypeScript:
  - 실행 방식: 트랜스파일
  - 특징: TS → JS → 엔진 실행
