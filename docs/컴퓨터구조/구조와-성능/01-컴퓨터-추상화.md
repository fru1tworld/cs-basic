# 컴퓨터 추상화

컴퓨터 시스템은 하드웨어와 소프트웨어가 여러 층으로 맞물려 동작한다. 프로그램을 작성할 때 이 모든 층의 세부사항을 직접 다루기는 어렵다. 그래서 추상화(Abstraction)를 통해 하위 계층의 복잡한 동작을 숨기고, 상위 계층에서는 필요한 인터페이스를 사용하도록 한다.

## 추상화 계층 (Abstraction Layers)

사용자가 보는 응용 프로그램에서 물리적인 반도체 소자까지 내려가면, 같은 시스템을 서로 다른 수준에서 설명하게 된다.

| 계층 | 설명하는 대상 |
| --- | --- |
| Application (응용 프로그램) | 사용자가 보는 프로그램 |
| Algorithm (알고리즘) | 문제를 해결하는 방법 |
| Programming Language (언어) | 해결 방법을 표현하는 고급 언어 |
| Operating System (운영체제) | 하드웨어 자원 관리 |
| Instruction Set Architecture (ISA) | 소프트웨어와 하드웨어 사이의 인터페이스 |
| Microarchitecture (마이크로아키텍처) | ISA의 구현 |
| Logic (논리 회로) | 게이트와 레지스터 |
| Circuit (회로) | 트랜지스터 수준의 동작 |
| Device (소자) | 물리적 반도체 |

## 각 계층의 역할

### Application (응용 프로그램)

Word, Chrome, 게임처럼 사용자가 직접 상호작용하는 계층이다. 사용자는 하위 계층의 구현을 알지 못해도 프로그램을 사용할 수 있다.

### Algorithm (알고리즘)

알고리즘은 문제를 해결하는 절차다. 특정 언어의 문법과 분리해서 해결 방법을 설명하고, 시간 복잡도와 공간 복잡도로 필요한 비용을 분석한다.

### Programming Language (프로그래밍 언어)

Python, Java, C++ 같은 고급 언어는 하드웨어의 세부사항을 추상화한다. 작성한 프로그램과 기계가 실행하는 명령 사이의 처리는 컴파일러나 인터프리터가 맡는다.

### Operating System (운영체제)

운영체제는 CPU, 메모리, I/O 자원을 관리하고 이를 프로세스, 파일 시스템, 네트워크 등의 추상화로 제공한다. 프로그램은 시스템 콜(System Call)을 통해 이 서비스를 사용한다.

### Instruction Set Architecture (ISA)

ISA는 소프트웨어와 하드웨어 사이의 인터페이스로, 이 구분에서 가장 중요한 추상화 계층이다. 프로그래머가 사용할 수 있는 명령과 하드웨어의 동작을 정의한다.

### Microarchitecture (마이크로아키텍처)

마이크로아키텍처는 ISA를 실제로 구현하는 방법이다. 같은 ISA라도 Intel Core와 AMD Ryzen처럼 구현은 달라질 수 있으며, 파이프라인과 캐시, 분기 예측 등이 이 계층에 속한다.

### Logic (논리 회로)

논리 회로에서는 AND, OR, NOT 같은 논리 게이트로 레지스터, 멀티플렉서, ALU의 동작을 구성한다. RTL(Register Transfer Level)은 레지스터 사이의 데이터 이동과 연산을 기술하는 설계 수준이다.

### Circuit (회로)

회로 계층에서는 트랜지스터 수준으로 내려가 전압, 전류, 타이밍을 분석한다. 논리값으로 표현했던 동작을 구현하려면 이 단계에서 아날로그 특성도 고려해야 한다.

### Device (소자)

소자 계층은 MOSFET과 CMOS 기술 등 물리적인 반도체를 다룬다. 회로를 구성하는 소자가 어떤 물리적 특성으로 동작하는지 설명하는 영역이다.

## ISA: 가장 핵심적인 추상화

ISA(Instruction Set Architecture)는 운영체제·컴파일러·응용 프로그램과 마이크로아키텍처·논리 회로 사이의 계약이다. 소프트웨어는 이 계약에 따라 명령을 사용하고, 하드웨어는 명령의 동작을 구현한다.

### ISA가 정의하는 것

- 명령어 집합: 사용 가능한 연산들
- 레지스터: 개수, 크기, 용도
- 메모리 모델: 주소 지정 방식, 정렬 규칙
- 데이터 타입: 정수, 부동소수점 크기
- 예외/인터럽트: 처리 방식

### ISA의 장점

- 호환성: 같은 ISA면 모든 구현체에서 실행 가능
- 유연성: 하드웨어 구현을 자유롭게 변경 가능
- 지속성: 수십 년간 호환성 유지 (x86은 1978년부터)

## 추상화의 장단점

### 장점

하위 계층의 구현을 모두 이해하지 않아도 인터페이스를 바탕으로 개발할 수 있으므로 생산성과 재사용성이 높아진다. 복잡성을 계층별로 나누어 관리하고, 한 계층의 변경이 다른 계층에 미치는 영향도 줄일 수 있다.

### 단점

추상화 계층을 거치는 데 비용이 들거나, 하위 계층을 직접 제어할 수 없어 최적화가 제한될 수 있다. 하위 계층의 특성이 밖으로 드러나기도 하므로, 문제가 생겼을 때는 여러 계층을 따라가며 원인을 찾아야 한다.

## 누수 추상화 (Leaky Abstraction)

이처럼 하위 계층의 특성을 완전히 숨기지 못하는 경우를 누수 추상화(Leaky Abstraction)라고 한다. 다음 코드는 같은 배열을 초기화하지만 순회 순서가 다르다. 이 차이가 메모리 접근 패턴을 바꾸어 캐시의 영향을 드러낸다.

```java
// 예시: 메모리 접근 패턴이 성능에 영향
// 추상화 관점에서는 동일해야 하지만, 캐시 때문에 성능 차이 발생

// 행 우선 순회 - 캐시 친화적 (빠름)
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        arr[i][j] = 0;

// 열 우선 순회 - 캐시 비친화적 (느림)
for (int j = 0; j < N; j++)
    for (int i = 0; i < N; i++)
        arr[i][j] = 0;
```

배열에 접근하는 코드만 보면 같은 작업이지만, 메모리 추상화가 캐시 계층의 특성까지 없애 주지는 않는다. 성능을 이해하려면 추상화 아래의 접근 방식도 살펴봐야 한다.
