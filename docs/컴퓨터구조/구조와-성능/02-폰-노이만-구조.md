# 폰 노이만 구조

폰 노이만 구조는 1945년 존 폰 노이만이 제안한 컴퓨터 설계 모델이다. 프로그램과 데이터를 같은 메모리에 저장하는 저장 프로그램 개념(Stored Program Concept)이 핵심이며, 오늘날 대부분의 컴퓨터도 이 구조를 기반으로 한다.

## Stored Program Concept (저장 프로그램 개념)

ENIAC처럼 배선으로 프로그램을 구성하는 컴퓨터는 실행할 작업을 바꾸려면 물리적인 배선을 변경해야 했다. 저장 프로그램 방식에서는 명령어도 데이터처럼 메모리에 넣는다. 따라서 프로그램을 바꿀 때 메모리 내용을 수정하면 되고, 같은 하드웨어로 다양한 작업을 실행할 수 있다.

## 폰 노이만 구조의 구성 요소

명령어와 데이터는 메인 메모리에 저장되고, CPU는 이를 가져와 해석하고 연산한다. CPU, 메모리, I/O 장치는 시스템 버스로 연결된다.

### CPU (Central Processing Unit)

CPU 안에서는 제어 유닛(Control Unit)이 명령어를 해석하고 실행을 제어한다. PC(Program Counter)는 다음에 실행할 명령어의 주소를, IR(Instruction Register)은 현재 실행 중인 명령어를 담는다.

실제 연산은 ALU(Arithmetic Logic Unit)가 맡는다. 덧셈·뺄셈·곱셈·나눗셈 같은 산술 연산과 AND·OR·NOT·XOR 같은 논리 연산을 수행하며, 연산에 필요한 데이터는 CPU 내부의 고속 저장 공간인 레지스터에 임시로 보관한다.

### 메모리 (Memory)

메모리는 명령어와 데이터를 함께 저장하며, CPU는 선형 주소 공간의 주소를 통해 접근한다. 여기서 다루는 메인 메모리는 휘발성이므로 전원을 끄면 데이터가 사라진다.

### I/O 장치 (Input/Output)

I/O 장치는 컴퓨터와 외부를 연결한다. 키보드·마우스·센서는 입력을 전달하고, 모니터·프린터·스피커는 처리 결과를 출력한다.

### 시스템 버스 (System Bus)

시스템 버스는 전달하는 정보에 따라 다음과 같이 나뉜다.

| 버스 | 역할 | 방향 |
| --- | --- | --- |
| 주소 버스(Address) | 메모리 주소 전달 | 단방향 |
| 데이터 버스(Data) | 데이터 전송 | 양방향 |
| 제어 버스(Control) | 읽기·쓰기 등의 제어 신호 전달 | 양방향 |

## 명령어 실행 사이클 (Fetch-Decode-Execute)

명령어 하나를 처리하는 흐름은 인출, 해독, 실행으로 나눠 볼 수 있다.

1. 인출(Fetch): PC가 가리키는 메모리에서 명령어를 가져와 IR에 넣고, PC를 다음 명령어 위치로 옮긴다.
2. 해독(Decode): 명령어의 연산 종류와 피연산자를 파악한다.
3. 실행(Execute): ALU 연산이나 메모리 접근 등 명령어가 지정한 작업을 수행한 뒤 다음 사이클로 넘어간다.

다음 의사 코드는 이 흐름을 반복문으로 표현한다. PC는 단순화해서 1씩 증가시키며, 분기 명령을 만나면 지정된 주소로 바꾼다.

```python
# 의사 코드로 표현한 명령어 실행 사이클
while True:
    # Fetch: 메모리에서 명령어 가져오기
    instruction = memory[PC]
    PC = PC + 1

    # Decode: 명령어 해석
    opcode, operands = decode(instruction)

    # Execute: 명령어 실행
    if opcode == "ADD":
        registers[operands.dest] = registers[operands.src1] + registers[operands.src2]
    elif opcode == "LOAD":
        registers[operands.dest] = memory[operands.address]
    elif opcode == "STORE":
        memory[operands.address] = registers[operands.src]
    elif opcode == "JUMP":
        PC = operands.address
    # ... 기타 명령어
```

## Von Neumann Bottleneck (폰 노이만 병목)

이 실행 흐름에서는 명령어를 가져올 때도, 데이터를 읽고 쓸 때도 메모리에 접근한다. CPU와 메모리 사이의 버스를 함께 사용하므로 두 종류의 접근이 경쟁하고, CPU의 연산이 빨라져도 메모리가 따라오지 못하면 기다리는 시간(Memory Stall)이 생긴다. 이를 폰 노이만 병목이라고 한다.

대기 시간을 줄이기 위해 CPU와 메인 메모리 사이에 고속 버퍼인 캐시를 두고, L1·L2·L3처럼 여러 계층으로 구성한다. 필요한 데이터를 미리 가져오는 프리페칭도 같은 문제를 완화하는 방법이다. 명령어와 데이터의 접근 경로를 분리하는 하버드 구조는 경로 자체를 바꾸는 접근이다.

## Harvard Architecture (하버드 구조)

하버드 구조는 명령어용 메모리와 데이터용 메모리, 그리고 각각의 버스를 분리한다. 따라서 명령어와 데이터에 동시에 접근할 수 있어 대역폭과 파이프라인 효율을 높일 수 있다.

현대 프로세서에서는 이 방식을 일부 계층에 적용한 수정 하버드 구조(Modified Harvard)도 사용한다. 예를 들어 CPU에 가까운 L1 캐시는 명령어용 I-Cache와 데이터용 D-Cache로 나누고, 그 아래의 L2 캐시와 메인 메모리는 통합한다. 가까운 계층에서는 접근 경로를 분리하면서도 메인 메모리는 함께 사용하는 구성이다.
